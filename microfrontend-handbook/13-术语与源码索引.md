# 13 术语与源码索引

## 1. 容易混用的术语

| 术语 | 在本仓库中的含义 |
| --- | --- |
| 基座／主应用 | 初始化运行时、提供容器并管理子应用的应用；Freelog 中 PC／移动入口还装配节点与授权 UI |
| 主题 | 负责节点页面整体呈现的子应用；不能据此认定所有平台授权都由主题实现 |
| 插件 | 被主题或插件挂载的子应用实例，可以来自展品或依赖位置 |
| 资源／展品／依赖位置 | 平台不同业务对象；微应用 name 是运行实例标识，不是这些业务 ID 的替代 |
| HTML Entry | 从入口文档解析所需 JS/CSS 与节点，随后在容器和沙箱中运行 |
| Custom Element | 浏览器自定义元素机制；MicroApp 注册的元素承接连接、属性变化和移除通知 |
| realm | JavaScript 全局环境与内建对象集合；独立 realm 不自动等于独立安全权限或独立可见 DOM |
| Proxy／with | 对象访问拦截／标识符查找调整；用于实现部分执行环境适配 |
| scopeProperties | 沙箱属性的独立读取规则，不是平台资源的访问授权 |
| escapeProperties | 允许部分值反映到真实宿主全局的兼容机制，需要评估污染与恢复 |
| DOM scope | 节点及操作的应用归属，不等同于浏览器原生 Shadow DOM |
| scoped CSS | 用选择器改写等限制样式作用范围；仍存在继承、全局规则和 CSSOM 等边界 |
| UMD 模式 | 此处由 mount/unmount 钩子决定的生命周期复用模式；与文件扩展名或构建格式不可混同 |
| keep-alive | 保留应用状态，通常转移 DOM 并保存部分副作用；隐藏不等于销毁或暂停所有工作 |
| destroy | 更彻底淘汰实例的框架操作；不等于清空页面所有共享资源 Map |
| fiber | 此实现的空闲任务调度方式；不是 Worker，也不自动抢占任意长同步任务 |
| search／state／pure | 子应用路由与主页面 URL／history.state 的不同映射协议 |
| EventCenter | 当前同页异步浅合并的数据通信中心；不是自动深拷贝的 RPC 或可靠事件队列 |
| loader 插件 | JS 代码转换接缝；和业务中的“插件子应用”是两个不同概念 |
| 工作区依赖 | 把包解析到本地目录；执行入口还取决于 module/main/alias，不一定读取 src |

## 3. 能独立回答的十个问题

1. 为什么打开子应用 URL 成功，不代表跨源 fetch、ESM 或平台授权成功？
2. 两次 `onLoad` 分别证明什么，哪些脚本还没执行？
3. with 的 `get/has/set` 如何共同影响裸变量和 `window.x`？
4. iframe 沙箱的可见 DOM 在哪，哪些能力仍共享？
5. 为什么 CSS 有前缀，`:root`、动画、继承或弹层仍需要实验？
6. 为什么子应用的 `history.go(-1)` 不一定只有子应用受影响？
7. 通信浅合并与缓存为什么不能充当逐条业务事件？
8. 普通卸载、UMD、keep-alive、destroy 分别保留什么？
9. `bindName` 绑定了什么，它为什么不是平台安全凭据？
10. 修改了 src，如何证明类型消费者和浏览器都取得了新产物？

把答案写成“函数＋输入／状态／输出＋一个实验”，并与第 11 章结果相互核对。先自己写，再展开 [第 14 章的参考推理](14-自测答案与进阶挑战.md)；答不出时按对应回读入口补当前缺口。
