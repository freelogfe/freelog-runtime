# 11 实验：从看见现象到解释机制

[返回目录](README.md) · [完整推理案例](CASE-STUDY.md) · [自测与答案](14-自测答案与进阶挑战.md)

本页是第三部的MicroApp实现实验。先完成 [不依赖MicroApp的底层实验](FOUNDATION-EXPERIMENTS.md) 与 [独立架构](architecture/01-从需求推导微前端边界与方案.md)，再用这里的现成引擎检验实现；两个实验目录与端口各自独立。

先用自带实验台观察真实 MicroApp，再回到 Freelog 测试节点。每项都按“预测 → 操作 → 看证据 → 解释”完成；看见页面渲染出来只是起点。

## 1. 两种环境的边界

| 环境 | 真实执行什么 | 不代替什么 |
| --- | --- | --- |
| 自带机制实验台 | 当前 `lib`、经典脚本 A/B、with／iframe、路由与通信 | 平台 SDK、文件授权、原生 ESM 依赖、完整浏览器兼容矩阵 |
| Freelog 测试节点 | 当前主题／插件、展品和依赖身份、真实 SDK 与授权 | 其他环境和生产部署的验收 |

另有 [异步教学模型](examples/pending-result.mjs)：它执行确定性 Promise 排程，专门解释结果提交权，不导入引擎。三种证据各有用途，不互相冒充。

## 2. 一条命令启动机制实验台

在仓库根目录：

```powershell
node microfrontend-handbook/labs/serve.mjs
```

打开默认 [http://127.0.0.1:4318/](http://127.0.0.1:4318/)。端口占用可用 `--port 4321`，退出按 `Ctrl+C`。服务只监听本机，按白名单提供讲义样本和现有引擎，不把仓库整体暴露为静态目录。

页面显示实际 `engineSource / packageVersion / engineSha256`。这是当前已构建 `lib` 的实验，不会自动重新编译 `src`。它是 bundler ESM，页面在加载前提供一项明确的 `process.env.NODE_ENV` 教学桥接，等价于处理构建环境条件；引擎文件本身不改字节。产物缺失时先解决构建来源，不换 CDN 版本。

### 先认识三个观察窗口

| 窗口 | 你应该看什么 | 避免的误判 |
| --- | --- | --- |
| A/B 插槽 | 实际 UI、内部导航按钮、计时 | UI 消失不等于实例销毁 |
| 当前快照 | 引擎应用列表＋子应用主动上报的 probe、ticks、cleanups | probe 在挂载、导航、恢复等主动报告时更新，不是全字段实时监控 |
| 因果记录 | 文本资源请求、框架事件、子应用报告、通信 | 两条日志相邻不等于它们拥有同一生命周期或授权语义 |

开始时保持 `with · 经典脚本 / search / 保留隐藏状态`。一轮实验结束可销毁 A/B，再选择其他配置；切换配置后直接“显示”旧实例不会更换它的沙箱。

## 3. 第一关：同代码，两个实例

**先预测：** 两份代码都使用 `#player-root`，A/B 是否拿到同一 DOM？普通 `window.__LAB_OWNER__` 会不会写到宿主？

**操作：** 依次点击“挂载 / 显示 A”“挂载 / 显示 B”，在快照中找到各自的 probe。

**预期：**

```text
apps.reader-a.probe.owner = reader-a
apps.reader-b.probe.owner = reader-b
两者 queryIsSelf = true
两者 rawHasOwner = false
with 经典脚本的 sameArrayConstructor = true
```

主页面存在两个同名 ID 并不是推荐的一般网页规范；这里故意构造同名根节点，用来观察代理查询是否选择各自容器。不能用顶层 Console 的 `document.querySelector` 代替子应用内部查询实验。

**解释：** 普通全局属性、DOM 查询与构造器来源是三件事；一项成功不能证明其余全部隔离。解释不清时读第 05、06 章，先跟一个 get 和一次 query，不打开所有源码。

## 4. 第二关：消息为什么合并，URL 为什么变化

在 A 内点击“同步发送两次消息”。记下点击前后的 `messages` 与 `lastMessage`；初次挂载还有 ready 消息，不要把总数直接当成本次发送次数。

**预期：** 同轮两次 dispatch 被观察为一份最终浅合并状态，含 `first: 1`、`second: 2`、`from: reader-a`。这证明当前样本的状态合并，不证明有一条可靠逐条命令队列。

再点击 A 的“内部导航到 /chapter/2”。

**预期：** 子应用报告 `/chapter/2`，真实浏览器 URL 带上以 `reader-a` 为键的编码信息；B 保持自己的路由。地址可能含编码字符，比较字段含义，不要求逐字符背诵某个固定 URL。

**解释：** 路由在一个真实地址栏上投影多个实例；消息在一个同页中心按通道分区。分别回第 07、08 章查路径映射和异步浅合并。

## 5. 第三关：隐藏、恢复、卸载、销毁

1. 隐藏 A，稍等约一秒后刷新快照。A 的 ticks 不再增长，B 继续增长；`activeApps` 可仍含 A，`visibleApps` 排除 A。
2. 再显示 A。观察 mounts 保持原值，计时恢复；这是保留实例的恢复。
3. 销毁 A。`allApps` 不再含 A，`cleanups` 增加，B 保持工作。

**关键解释：** A 的计时停止是 [child.js](labs/child.js) 在 `afterhidden` 中调用 stopTimer 的结果。样本主动暂停，不代表沙箱自动暂停所有定时器。真正卸载时，样本还移除自己的 DOM／数据／window 监听。

需要对比普通 UMD 卸载和再次 mount 时，在实验页顶层 Console 使用下面的**宿主观察接口**，不在子 iframe Console 中运行：

```js
var lab = window.__HANDBOOK_LAB__
await lab.mount('reader-a')
await lab.unmount('reader-a', { clearAliveState: true })
console.log(lab.snapshot()) // 状态 unmount；不是 afterhidden
await lab.mount('reader-a')
console.log(lab.snapshot()) // mounts 增加，重新调用了子应用 mount
```

这份样本提供 mount/unmount 钩子，因此是 UMD 生命周期模式。它不能单独证明没有钩子的 default 模式怎样清理。清理范围与所有权见第 08 章。

## 6. 第四关：换成 iframe，再问一次“隔离了什么”

先销毁 A，再选 `iframe · 经典脚本`，保持 B 不变并重新挂载 A。

**预期：** A 的 `sameArrayConstructor=false`，说明用了另一套构造器；`queryIsSelf=true`，可见根仍出现在主页面的 A 容器中，B 不受此次销毁和重建影响。

**解释：** realm 分开与可见 document 分开不是一件事。这个样本还是经典脚本，不含 Vite／原生 module；要判断 module 请求与 loader 边界，先看第 05 章矩阵，再用实际 ESM 产物单独验证。

## 7. 观察不符合预期时，从这里分流

| 观察 | 下一份证据／动作 |
| --- | --- |
| 启动即找不到 lib | 检查 `packages/micro-app2/lib/index.esm.js`，按第 12 章核对构建，不安装远端包替代 |
| 端口占用或页面打不开 | 换端口，看终端原始错误；确认使用 http 地址，没有用 file 双击 HTML |
| 一直“加载中” | 最早控制台错误＋因果记录＋第一个失败资源；不要盲目重复挂同名实例 |
| 选择新配置后还是旧沙箱 | 先销毁，再新建；隐藏恢复保留的是原实例 |
| Console 找不到 lab | 选择实验页顶层执行上下文，等待页面显示“已就绪” |
| A/B 的宿主查询拿到第一项 | 检查你是否误用了宿主 query；应看子应用上报的 queryIsSelf |
| 消息数比预期大 | 分开初次 ready、当前操作和历史缓存；看 `from` 与前后差值 |
| 断言与当前构建不符 | 保存 lib 摘要、输入和最早证据，先作为待解释差异，不直接宣布线上缺陷 |

刷新整个实验页可重新开始教学记录，但不要把刷新当成业务修复。超时只表示外层等待结束，不表示下载或应用工作已自动取消。

## 8. 第五关：不用慢网碰运气的异步故障

```powershell
node microfrontend-handbook/examples/pending-result.mjs
node --test microfrontend-handbook/examples/pending-result.test.mjs
```

先预测 old/new 的绘制顺序，再读 [完整案例](CASE-STUDY.md)。正确模型应只提交 new；A 的退出不影响 B。你需要解释：为何布尔 active 不足、代次验证在哪一步、abort 又负责什么。这次实验是纯业务教学模型，不是修改内核。

完成后做第 14 章迁移题：把旧请求成功换成旧请求失败，或让用户不退出但切换章节。能写出新断言，才算通过这一关。

## 9. 接回 Freelog 的平台实验

前五关无需账号。下一轮才使用已有测试节点，分别加载展品插件与依赖插件，记录 `name / exhibitId / topExhibitId / nid / parentNid` 的来源。

按第 09 章串起 SDK 初始化 → 当前依赖身份 → 内容查询 → 实际文件读取 → 子插件挂载 → 消息 → 清理。授权允许与不允许分别检查；列表可见、签约成功、文件可读不能互相替代。

平台实验、跨源 CORS／凭据、原生 module、后退／刷新／分享完整矩阵、capture 监听器和堆内存压力都需要单独运行。机制样本成功不扩大到这些结论；实际已执行范围见 [VALIDATION](VALIDATION.md)。

## 10. 未来改动怎样选择最小回归

| 改动位置 | 先验证的因果链 | 再按影响扩展 |
| --- | --- | --- |
| URL 补全／平台文件 fetch | 真实入口输入输出、静态与动态资源 | CSS url、ESM、授权、路由基址 |
| 沙箱／DOM／CSS | A/B 查询、全局、弹层、目标规则 | realm、动态节点、重挂、capture 清理 |
| 路由 | 当前模式 push/replace 与实例状态 | 后退前进、分享刷新、隐藏恢复、宿主参数 |
| 通信／生命周期 | 当前消息合同与资源账本 | 重复进入、异步竞态、宿主订阅、父子控制器 |
| 构建／类型入口 | 消费者读到的新声明与新字节 | PC／移动构建、真实浏览器、平台节点 |

定向失败回归先通过，再扩展受影响组合。每条结果写明“版本、输入、操作、观察、解释、尚未验证”，不要用“实验通过”代替具体行为。
