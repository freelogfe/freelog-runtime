# 自动化与结果处理

::: info CLI 同步文档
本页自动同步自 CLI 仓库使用手册。先核对已安装版本与本页适用范围；Node.js 22.14+ 是 CLI 自身要求，不是运行时对子应用的要求。来源、发布状态及已知限制见[版本说明](/about)。
:::


本页适合让 AI 或脚本分步调用 CLI。先按业务教程确认目标、账号、环境和输入，再根据退出码、结果字段及读回决定下一步；不要把命令参考整页拼成脚本。

## 先判断结果，再继续操作

1. 使用精确的资源、节点或展品 ID，通过 `--cwd` 明确工程目录。需要保留工作稿时，先查看再决定是否覆盖。`--yes` 仍会执行所有业务校验。
2. 机器结果仅在命令支持时使用 `--json`。普通失败出口顶层包含 `code`、`message`、`category` 和 `outcome`，参数解析失败也遵守该契约。具名批次或复合结果保留自己的结构，失败条目的四字段可能在 `error` 内；先按该命令的结果结构定位错误，不假定所有结果都是顶层四字段。分类和退出码见[错误输出与退出码](./09-常见情况与报错.md#参数解析错误和-json-输出)。
3. 成功数据仍按各命令分别定义，参见[成功输出参考](./11-命令参考.md#ai与脚本读取成功结果)。不要假定所有成功结果都含同一组字段，`--help`和版本查询仍输出文本。
4. 非零退出时停止后继写入。`outcome=unknown`时保留现场并查询或恢复，`pending`时核实处理或收尾进度；都不能直接重发。错误 JSON 能解析不代表业务成功。
5. 退出 0 后继续检查业务字段。例如准备版本不是发行完成，`isAuth=false`是授权查询成功但尚未授权；最后按教程读回目标与实际状态。

人工先看[退出码的中文含义](./09-常见情况与报错.md#退出码与处理)，AI按原始字段分流：`category`表示问题类别，`outcome`区分错误、未知、待处理或取消。成功结果不要求统一category/outcome，不能给退出0的结果补造`category: "success"`，也不能把unknown或pending合并成普通失败后重发。

机器模式的 JSON 写入 stdout，诊断信息写入 stderr；不要把两个流合并后再解析。格式错误应先修命令，平台明确拒绝按安全的后端 `message`处理；网络超时和真正未知写入的下一步见[故障恢复](./09-常见情况与报错.md)。

以下模板处理已登录的普通业务。验证码由用户本人完成；收费、期限、签约策略和付款等具体商业选择仍由人确定，AI按对应教程的当前支持范围执行，不自行替用户作这些选择。

## 脚本最小安全模板

下面仅适用于已绑定且已有线上版本的资源，不是首次发行模板。统一使用同一资源 ID；先只读核对目标、latest、本地工作稿有无和默认产物路径：

```powershell
freelog-cli status --cwd <工程> --resource id:<资源ID>
freelog-cli version show --cwd <工程> --resource id:<资源ID>
```

确认没有要保留的旧稿、本次新文件已经存在，才建立更新稿并提交。替换占位符后，将**整个脚本块**作为一个单元执行（或保存为 `.ps1` 执行）；每条外部命令后显式检查退出码。不要逐行跳过检查，也不要用捕获后继续的逻辑吞掉错误：

```powershell
& {
    freelog-cli version draft pull --cwd <工程> --resource id:<资源ID>
    if ($LASTEXITCODE -ne 0) { throw "拉取失败，停止提交；退出码：$LASTEXITCODE" }

    freelog-cli update-version --cwd <工程> --resource id:<资源ID> --artifact video-v2.mp4 --bump patch --yes
    if ($LASTEXITCODE -ne 0) { throw "提交未确认成功，停止后续操作并核实结果；退出码：$LASTEXITCODE" }

    freelog-cli version show --cwd <工程> --resource id:<资源ID>
    if ($LASTEXITCODE -ne 0) { throw "查询失败，不代表提交失败；退出码：$LASTEXITCODE" }
}
```

pull 未加 --yes，非交互遇到已有稿会停止而不是覆盖；上述退出码检查确保前一步失败时不继续 update-version。这里是 PowerShell 语法，macOS 的 bash/zsh 脚本需使用其对应的失败停止机制，不能直接粘贴此块。需要保留或编辑稿时改走[更新完整教程](./04-日常路径.md#接入已有资源并发布新版本)。

需要机器可读错误时追加 `--json`。脚本优先用 `id:`、完整 `name:` 或 `file:N.json`；标题只作展示，不能作为选择器，也不要依赖交互式选择。

### AI自动化中的参数保真

Windows的`.cmd`包装器、PowerShell及bash/zsh有各自的引号规则。输入的空格、`^`、`|`到达CLI前就可能被shell处理，CLI不能恢复已经丢失的字符。Node脚本建议直接执行已安装包的`dist/bin/index.js`，使用参数数组并保持`shell:false`，不拼接shell命令。例如将下面保存为`.mjs`，替换目标和范围后在已登录工程执行，并通过第一个脚本参数提供CLI入口的绝对路径：

```javascript
import { spawnSync } from 'node:child_process';
const cliEntry = process.argv[2];
if (!cliEntry) throw new Error('需要已安装CLI的dist/bin/index.js绝对路径');
const result = spawnSync(process.execPath, [
  cliEntry, 'version', 'dep', 'add', 'username/resource-name',
  '--range', '^1.0.0 || ^2.0.0', '--resource', 'id:<资源ID>',
], { shell: false, stdio: 'inherit' });
process.exitCode = result.error || result.signal ? 1 : result.status ?? 1;
```

这只减少shell转义层，不保证交互输入和Ctrl+C在所有终端中表现相同。连续属性命令也各自保存，后一步失败不会撤销前面的成功；先查看工作稿再决定如何继续，不能整体盲重试。
