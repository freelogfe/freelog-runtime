# 单资源：资料与上下架管理

::: info CLI 同步文档
本页自动同步自 CLI 仓库使用手册。先核对已安装版本与本页适用范围；Node.js 22.14+ 是 CLI 自身要求，不是运行时对子应用的要求。来源、发布状态及已知限制见[版本说明](/about)。
:::


本页管理本人单资源。查询资料只需要登录正确账号；版本、修改及上下架等工程操作还需要目标已 create 或 bind。示例明确使用 dev 环境；修改线上资料不会发行新版本，也不改下一版本的工作稿。

操作前按[版本选择](./00-版本选择与AI代办.md)核对实际安装来源及当前可用范围。

## 查看现状

先查线上标题、简介、标签、封面、资源状态与最新版本：

```powershell
freelog-cli resource show <资源ID> --env dev
freelog-cli resource show username/name --json --env dev
```

位置参数必须是精确资源ID或完整授权标识，不是标题。该路径可以读取本人未绑定到当前工程、尚未发行版本、已下架或被冻结的资源；不会自动bind，也不读取或修复当前工程的资源稿、未决记录。其他人的公开资源请用`market show`查询。

已经在工程管理的资源也可以按本地身份选择：

```powershell
freelog-cli resource show --resource id:<资源ID> --json --env dev
```

本地选择器还支持`name:username/name`、`artifact:picture.png`和`file:1.json`。位置参数不能与`--resource`一起使用。省略两者时，唯一身份自动选择；多身份的普通终端可按提示选择，JSON或非交互调用必须显式指定。按本地身份查询仍会校验工程状态一致性；如果工程稿损坏但需要独立核对线上资料，使用精确位置目标。

`--json`只输出一个资料对象，字段为`resourceId`、`resourceName`、`resourceTitle`、`resourceTypeCode`、`subjectType`、`userId`、`intro`、`tags`、`coverImages`、`status`、`latestVersion`。`latestVersion:""`表示尚无版本；`status`按下表读取：

| status | 资源状态 |
|---|---|
| 0 | 未发行 |
| 1 | 公开上架 |
| 2 | 冻结 |
| 4 | 下架 |
| 8 | 非公开上架 |

查询不会刷新本地标题、改稿、上架或发行版本。请求失败或账号/环境在等待中变化时，非零退出并显示受控错误，不输出旧账号或不完整的成功资料。

需要进一步查看工程工作稿、线上版本内容或授权策略时，分别执行：

```powershell
freelog-cli status --resource id:<资源ID> --env dev
freelog-cli version show --resource id:<资源ID> --env dev
freelog-cli policy list --resource id:<资源ID> --env dev
```

status 汇总身份、工作稿与线上 latest；version show 读取线上版本，policy list 读取自身策略。`version show` 在交互终端列出已发行版本供选择，latest 在首位；取消不会读取版本详情。脚本或加 `--yes` 时默认读取 latest，指定历史版用 `--version 1.0.0`（必须是已发行版本）。只看未提交稿则加 `--local`，两种用途不要混淆。

线上版本查看和拉取工作稿都要求登录、资源属于当前账号且未冻结；平台返回的资源和版本必须与请求一致，否则失败。`version show --local` 只读本地稿，无需登录。pull 在覆盖前再次核对线上权限，失败时保留原稿。

status当前成功结果为三段文本，不提供成功JSON或完整上下架资料；需要这些资料用`resource show`。未绑定时显示“线上：未查询”，不请求平台；绑定后只接受同一资源的有效详情。平台明确没有版本时显示`latestVersion=无`；缺失/错ID、畸形版本或请求失败均非零退出，不用本地缓存补造线上现状。它不会刷新标题、修改稿或清未决记录，冻结/非本人也不额外套用写权限门禁；需要恢复另用resource recover。

## 修改展示信息

只发送明确给出的字段。下面同时修改标题、简介和标签；先把示例内容换成自己的：

```powershell
freelog-cli update --title "新标题" --intro "一句话简介" --tags "教程,图片" --resource id:<资源ID> --yes --env dev
```

只改一个字段时删掉其它字段参数，不必全填。要换封面，先准备工程内图片，再执行独立操作：

```powershell
freelog-cli update --cover cover.png --resource id:<资源ID> --yes --env dev
```

封面支持 JPG、PNG、静态 GIF，最大 5MB，CLI 上传后写入 URL，**没有裁剪功能，也不支持清空封面**。标题最多 100 字符，简介最多 200 字符；最多 20 个不重复标签，每个最多 20 字符。标签可写 # 前缀，存储时去掉前缀。

清空简介用 `--intro ""`，清空全部标签用 `--tags ""`，不是保留原值。没有任何修改字段的 --yes 更新会拒绝，不发送空更新。TTY中也可以只运行`freelog-cli update --resource id:<资源ID> --env dev`，按提示逐项修改，回车保留；全部保留不发请求。有任一修改参数时只改指定字段，不额外询问其它字段。

CLI先显示当前资料、校验全部输入，再确认；确认前不上传封面、不写平台。确认后直接提交本次修改；封面上传后也不重新读取远端资料。确认期间在其它界面修改过资源不触发冲突拦截，写入资格由后端裁决。写后读取并核对本次提交字段，成功后同步本地标题；其它字段以读回现状展示，不与确认前快照比较。RSS导入资源的资料当前只读。

AI可给update加`--json`，成功只返回`{resourceId,changed,listing:{resourceName,title,intro,tags,coverImages,status}}`，字段来自实际读回；普通失败非零退出，返回`{code,message,category,outcome}`，按[错误输出与退出码](./09-常见情况与报错.md#参数解析错误和-json-输出)处理。`changed:false`表示没有需要写入的变更。出现`UPDATE_RESULT_UNKNOWN`或`UPDATE_VERIFY_FAILED`先核对网页资料，不要立即重发；线上成功但本地缓存失败会明确提示，用resource sync修复本地标题。

修改资料或已发版本说明时，资源查询成功且data:null会提示`RESOURCE_NOT_FOUND`：“资源不存在，请检查资源ID”，不继续发送修改。`RESOURCE_FROZEN`及其它前置拒绝不改变本地标题或版本稿；若封面已经上传，平台可能保留该图片，CLI不自动删除或重传。明确的后端业务拒绝会显示安全的原因；写入后的查询失败仍按结果未知处理，不能据此直接重试。

`--json`不代表自动同意。在交互终端，资源选择、字段输入和确认仍会执行，提示与答案写stderr，stdout只保留结果JSON；脚本请提供精确`--resource`、修改参数及`--yes`。

## 同步本地标题

标题可以重复，也可能被网页改过，只作展示，**不用标题定位资源，不默认先同步所有标题**。

要刷新当前环境全部已绑定单资源的本地标题：

```powershell
freelog-cli resource sync --env dev
```

若只想刷新一份，使用下面这条替代批量命令：

```powershell
freelog-cli resource sync --resource id:<资源ID> --env dev
```

同步只读线上并回写匹配身份的本地标题，不修改平台、版本稿或产物路径。部分失败时成功项已更新，失败项保持原值，命令非零退出并报告。CLI update --title 成功后已回写本地标题，无需立即再同步。

AI或脚本可获取逐项结果：

```powershell
freelog-cli resource sync --json --env dev
```

stdout只有一个对象，包含`schemaVersion:1`、`env`、`summary:{total,succeeded,failed}`和按状态编号升序的`results`。每项用`stateFile`和`resourceId`定位，`synced`项有`title`，`failed`项有`error:{code,message}`。部分或全请求失败时仍返回完整批次，并以error提供分类退出码（见故障恢复页）；不要把非零退出理解成成功项没更新。登录、状态或事务错误则返回普通`{code,message,category,outcome}`，不输出伪成功批次。只重试报告指出的失败目标；不要手工覆盖身份ID。

## 上架

资源必须有已发行版本和至少一条启用的自身策略；依赖签约不算自身策略。

```powershell
freelog-cli validate --for online --resource id:<资源ID> --env dev
```

这条只检查。读清结果，补齐缺失项后才执行：

```powershell
freelog-cli online --resource id:<资源ID> --yes --env dev
freelog-cli resource show <资源ID> --env dev
```

online默认公开上架，确认后只写status=1，再读回同一资源及owner，确认目标状态才显示成功。已经处于目标状态且前置合法时不重复写。加`--json`得到`{resourceId,status,changed}`。完整首次流程见[快速上手](./01-快速上手.md)，策略添加见[单资源授权策略](./07-单资源授权策略.md)。

### 非公开上架

希望资源不出现在公共市场和搜索，但仍允许知道链接的人查看、分享和按策略授权时，使用：

```powershell
freelog-cli online --visibility unlisted --resource id:<资源ID> --yes --json --env dev
freelog-cli resource show <资源ID> --json --env dev
```

成功状态为8，同样要求已有版本和启用策略。改回公开用`online --visibility public`，不是再次发行版本。它不是指定用户可见的权限控制，也不是下架；上架状态1或8均不能停用最后一条启用策略。当前CLI签到节点的授权模块尚未支持非公开来源，需要等待适配；浏览器是否支持以实际页面为准。本命令不替你签约。

## 下架

确实需要下架时执行，**不是上架后的下一步**：

```powershell
freelog-cli offline --resource id:<资源ID> --yes --env dev
freelog-cli resource show <资源ID> --env dev
```

只改变可用状态，不删除资源、历史版本、策略、本地身份或工作稿。offline写后强制读回status=4；原本为0或4时不写，保留原状态。它也支持`--json`的`{resourceId,status,changed}`。没有`--yes`的TTY会确认，脚本必须带`--yes`。出现`SHELF_RESULT_UNKNOWN`或`SHELF_VERIFY_FAILED`先核对网页状态，不盲目重试；不要从CLI下架操作自行推导已有合约的退款或解除规则。

## 其它管理与失败

- 自身策略启停见[策略教程](./07-单资源授权策略.md#启停已有策略)。
- 发新版、绑定已有资源见[日常路径](./04-日常路径.md)。
- 修改已发版本说明见[两种版本说明](./06-版本工作稿.md#_5-两种版本说明)，不是资源简介。
- 非 owner、被冻结或环境不符时写操作会拒绝，不因此删除本地稿。中断或结果未知先按[故障恢复](./09-常见情况与报错.md)只读核实；资料和策略更新不套用版本提交恢复器。
