# 依赖添加及管理中的授权

::: info CLI 同步文档
本页自动同步自 CLI 仓库使用手册。先核对已安装版本与本页适用范围；Node.js 22.14+ 是 CLI 自身要求，不是运行时对子应用的要求。来源、发布状态及已知限制见[版本说明](/about)。
:::


适用于普通单资源（包括主题/插件）和合集的依赖添加及已有依赖管理。依赖列表、版本范围、工作稿和发行操作分别看[版本工作稿](../06-版本工作稿.md)与[合集管理](../合集/02-发行后管理与边界.md)。

本轮开发稿的直接依赖来源可为线上单资源或作者合集；合集来源固定1.0.0。这与合集目录单品不同，不扩大单品来源类型，也不表示npm旧版已有本轮能力。

1. 确认当前资源或合集、环境、依赖来源及版本范围。合同的被授权方是当前资源或合集，不能以个人购买或节点合同代替。
2. 添加、修改范围或存储导入依赖只校验声明并保存本地稿，不查合同、不签约。声明成功不是已获授权；add/range不接受policy。
3. 到当前资源或合集的Console“依赖及其授权”核对依赖和必要上游、策略、合同及履约条件。当前CLI不代签依赖；已有依赖的后续签约和履约也使用这个入口，不只限首次添加。
4. 需要支付时由本人在正确合同下办理，见[支付与恢复](./支付与恢复.md)。发行校验接受适用的生效合同，未付款不额外阻止发行，但不表示文件已有访问授权；声明存稿本身不查合同。
5. 返回原资源或合集，核稿内依赖和范围后继续发行；现行发行前仍检查正确主体的适用合同。浏览器办理合同不会自动发行版本。摘要刷新若尚无包提供者将明确不可用，不能据此反复签约。

新的包授权命令和候选配置发行链已准备对接，但依赖授权内部开关当前关闭；等auth-cli业务完成并联合验收后统一开放，不提供用户绕过参数。当前节点签入的既有能力不受此开关影响。

修改范围不自动获取更广授权，移除本地依赖不等于终止合同或退款。未决签约先按原操作ID只读恢复，不因查不到合同就再次签约。命令、JSON及恢复参数以对应业务教程为准。
