# 支付与历史订单

::: info CLI 同步文档
本页自动同步自 CLI 仓库使用手册。先核对已安装版本与本页适用范围；Node.js 22.14+ 是 CLI 自身要求，不是运行时对子应用的要求。来源、发布状态及已知限制见[版本说明](/about)。
:::


当前开发稿暂停CLI内的新支付、预支付及二维码生成。请在Console为正确的资源、合集或节点合同办理支付；个人购买不替代这些主体的合同。未来签约与支付统一由内联auth-cli包提供，用户无需另装授权工具。

## 1. 到网页办理

dev使用[Console](https://console.devfreelog.com/)。资源/合集的直接依赖进入该资源或合集的“依赖及其授权”；展品来源授权进入所属节点的展品编辑页。先核对当前资源/合集/节点ID、合同、事件及金额，再由本人完成支付或其它履约。不能因为CLI已保存依赖或创建展品就认为已付款、已获得内容访问授权。

当前`payment start`和`payment qr`会说明暂停状态，不生成订单或二维码。AI不得换用旧版本自动续单、读取支付密码或代替用户确认付款。

`payment start <合同ID>`即可查看指引，不必补填已停用的event或method；旧参数仍可传入，但不会发起支付。

## 2. 查询已有合同与历史订单

历史查询入口保留，不创建新订单：

```sh
freelog-cli payment show <合同ID> --env dev --json
freelog-cli payment status <订单ID> --env dev --json
freelog-cli payment status <订单ID> --env dev --wait --json
```

show核验合同属于当前账号管理的资源/合集/节点，并读取当前支付事件；展示渠道不表示当前CLI支持发起该渠道支付。status仅查询当前账号本地记录指向的原订单及合同；`--wait`最多五分钟，不重叠请求、不重发预支付。没有本地记录的浏览器订单不能用此命令冒充已跟踪的原订单。

`paymentStatus`分别表示succeeded、failed、pending、unknown；`authStatus`是独立授权结果。查询退出0不等于已付款；也不能以“已授权”倒推支付成功，或保证依赖链已全部满足。

## 3. 保留现场

旧订单和二维码记录保留在用户目录`.freelog/payments/<env>/<userId>/`，不写工程或Git。未知、待处理、已拒绝或过期的旧单均不自动重发、换单或换渠道。保留订单ID，在网页或联系平台核对；不要手工删除记录后重付。

历史事实：0.7.0曾提供微信扫码，但这不是当前版本继续提供新支付的承诺。当前版本已暂停发起新支付，不要因旧教程或旧订单回退旧版重付；支持范围以本页及安装包为准。
