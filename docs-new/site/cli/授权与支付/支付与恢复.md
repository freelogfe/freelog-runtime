# 支付与历史订单

::: info CLI 同步文档
本页自动同步自 CLI 仓库使用手册。先核对已安装版本与本页适用范围；Node.js 22.14+ 是 CLI 自身要求，不是运行时对子应用的要求。来源、发布状态及已知限制见[版本说明](/about)。
:::


当前CLI不发起新支付、预支付或生成新二维码。请在对应环境的Console为正确的资源、合集或节点合同办理支付；个人购买不替代这些主体的合同。

## 1. 到网页办理

请进入与CLI命令相同环境（dev或test）的Console；dev入口为[Console](https://console.devfreelog.com/)。按原业务找到合同：

| 原业务 | 网页去向 | 办理后返回 |
|---|---|---|
| 资源或合集的直接依赖 | 当前资源或合集的“依赖及其授权” | [依赖工作稿及发行前校验](./依赖授权.md) |
| 首次签到节点后履约 | 所属节点的该展品编辑页 → “资源授权” | [签到节点后的授权检查与上架](./签到节点.md) |
| 已有展品的来源授权 | 所属节点的该展品编辑页 → “资源授权” | [合同应用与整体授权检查](./展品资源授权.md) |

先核对当前资源、合集或节点ID，以及合同、支付事件和金额，由本人完成支付或其他履约。随后在网页读回支付结果，并按上表返回原业务核对合同和实际授权。CLI已保存依赖或创建展品不表示已付款；付款成功也不代表所有授权条件已满足。

当前`payment start`和`payment qr`会说明暂停状态，不生成订单或二维码。AI不得换用旧版本自动续单、读取支付密码或代替用户确认付款。

`payment start <合同ID>`即可查看指引，不必补填已停用的event或method；旧参数仍可传入，但不会发起支付。

## 2. 查询已有合同与历史订单

历史查询入口保留，不创建新订单：

```sh
freelog-cli payment show <合同ID> --json
freelog-cli payment status <订单ID> --json
freelog-cli payment status <订单ID> --wait --json
```

show核验合同属于当前账号管理的资源/合集/节点，并读取当前支付事件；展示渠道不表示当前CLI支持发起该渠道支付。status仅查询当前账号本地记录指向的原订单及合同；`--wait`最多五分钟，不重叠请求、不重发预支付。没有本地记录的浏览器订单不能用此命令冒充已跟踪的原订单。

`paymentStatus`分别表示succeeded、failed、pending、unknown；`authStatus`是独立授权结果。查询退出0不等于已付款；也不能以“已授权”倒推支付成功，或保证依赖链已全部满足。

## 3. 保留现场

旧订单和二维码记录保留在用户目录`.freelog/payments/<env>/<userId>/`，不写工程或Git。未知、待处理、已拒绝或过期的旧单均不自动重发、换单或换渠道。保留订单ID，在网页或联系平台核对；不要手工删除记录后重付。

不要因旧教程或旧二维码回退旧版重付；先核实原合同和订单的实际结果，再决定后续处理。
