本页是单资源命令索引：列出当前单资源 CLI 命令、何时使用以及它会不会改变线上资源或本地文件。合集命令和场景请查独立的[合集使用教程](./合集/index.md)；首次完成单资源任务请优先看[按场景操作](./03-按场景操作.md)。

表格中的命令省略 `freelog-cli` 前缀和公共参数；可执行代码块保留前缀。平台操作推荐显式传 `--env dev` 或 `--env test`，工程不在当前目录时传 `--cwd <工程目录>`。常规目标操作在多资源工程中使用 `--resource <selector>`；账号、类型、工程模板、本地诊断不选择某一份资源。`create` / `bind` 有新增或接续规则，`resource sync` 可批量，`resource recover` 由未决记录固定目标。`--yes` 跳过交互确认但不放宽校验。详细选择规则见[首页](./index.md#多资源工程-先选身份-再给产物)。

以下[存储管理与发行导入](./存储空间/index.md)适用于 0.6.0+：`storage usage`、`storage bucket list/show/create/remove`及`storage list/show/upload/remove/recover`，存储命令不接受作者`--resource`。单资源init/create/bind/version set/create-version/update-version可用`--storage-object <id>`替代本地`--artifact`，两者互斥；远端身份使用id/name/file选择。`version draft import-storage <对象ID> --groups attributes,options,dependencies`显式按组选元数据，不顺带修改文件来源或发行。旧 npm 0.5.9 不包含这些能力；正式包可用后正常安装，发布前的包选择见[版本指南](./00-版本选择与AI代办.md)。

0.6.0+ 已有展品的`exhibit version set`及`exhibit version auto --on|--off`见独立的[展示版本管理](./节点与展品/index.md#_5-已有展品切换展示版本)，不使用作者资源选择器，也不发行资源版本；旧 npm 0.5.9 不包含这两个入口。

## 支付命令（0.7.0）

独立于作者资源选择，任何cwd均可用，不接受--resource；仍须当前账号、显式环境和正确合同。完整流程见[支付手册](./支付/index.md)。

| 命令 | 用途与副作用 |
|---|---|
| `payment show <contractId>` | 只读当前合同支付事件、原价和渠道 |
| `payment start <contractId> --event <id> --method wechat [--open]` | 保存订单并生成付款码PNG，本人扫码才付款；支付宝分支当前受dev后端阻塞 |
| `payment status <orderId> [--wait]` | 只读核原订单及合同，最多等待五分钟 |
| `payment qr <orderId> [--open]` | 用原链接重建图片，不创建新订单 |

## 公共资源匹配参数

一个目录可有多个视频、图片或其它资源；用户不需要记住 `.freelog/2.json`。对任何常规单资源命令使用同一个参数：

```text
--resource id:<资源ID>                 # 最稳定，推荐
--resource name:<username/name>         # 完整不可变标识，推荐
--resource artifact:<相对文件或目录>    # 例如 artifact:video.mp4
--resource file:N.json                 # AI、脚本、恢复时的精确状态文件
```

`--resource artifact:video.mp4` 是**选择**已记录为 `video.mp4` 的资源；发行命令中的 `--artifact video-v2.mp4` 才是本次上传新文件。二者可以同时出现。单份状态自动选择；多份状态在 TTY 展示标题、标识符、ID、产物和工作稿供选择，非交互则列出上述可复制候选并停止。标题重复时使用 `id:`、`name:`、`artifact:` 或 `file:`。

```powershell
freelog-cli --help
freelog-cli version --help
freelog-cli policy template apply --help
freelog-cli --cli-version
```

顶层 `--help` 会打印安装包内本手册的绝对路径；子命令 `--help` 显示该命令当前支持的选项。脚本不要从帮助文本解析业务结果；需要稳定错误结构时使用 `--json`。

## 账号、工程和类型

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `login [--global]` | 登录当前工作区；脚本可用 `--login-name`、`--password-stdin --yes`。 | 将秘密写入系统凭据库，并写入工作区或全局选择器。 |
| `logout [--global]` | 切换账号或清除本地登录选择。 | 只清选择器及明确孤立的凭据；不删除工程或线上资源。 |
| `init [dir] [--type <叶子类型>] --artifact <路径>` | 用已存在的普通文件，或主题/插件的文件/目录，创建未绑定本地身份。 | 新建未绑定 `N.json`，不创建线上资源；不会扫描或猜测产物。 |
| `init theme <dir> [--template <id>]` | 从主题模板创建新工程。 | 固定主题类型 `RT001` 与默认构建目录 `dist`。 |
| `init widget <dir> [--template <id>]` | 从插件模板创建新工程。 | 固定插件类型 `RT002` 与默认构建目录 `dist`。 |
| `template list` | 查看可用于主题/插件初始化的模板。 | 只读。 |
| `type list` | 列出全部可用最终叶子；每行显示 `code + 根 / … / 叶子`。固定每页 50 条，TTY 可翻页；非 TTY 输出首页和后续提示。 | 只读，需要登录。 |
| `type search [关键词]` | 按名称筛选最终叶子，输出与 `type list` 相同的完整路径和分页体验。 | 只读，需要登录。 |
| `type info <类型编号>` | 确认某个类型编号、从类型树取得的完整名称链和可选配置能力。只有详情显示“可选配置：支持”时，版本工作稿才允许 add/set 配置。 | 只读，需要登录。 |
| `type pick [--type <类型编号>]` | 以命令方式列出或确认一个最终叶子类型；无 `--type` 时使用与 `type list` 相同的完整路径和分页。通常 `init` 的交互选择已足够。 | 只读，需要登录。 |

通用 init 可以接入已有源码/素材目录，但不覆盖既有资源状态；模板 init 要求新目录、空目录或仅有允许的初始 `.freelog/`：其内容为空或仅有普通登录选择器 `auth`。其他状态条目或链接均拒绝。脚本必须明确提供目标目录（当前目录写 `.`），模板脚本还必须同时提供 `--template <id> --yes`。主题/插件既有项目可通过通用 init 明确传 RT001/RT002，不复制模板。

## 建立或接入资源身份

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `create --title <标题> --name <短标识> [--type <叶子类型>] [--artifact <路径>] [--resource <selector>]` | 线上还没有该资源壳时创建它。已有唯一未绑定身份时会接续它；没有未绑定身份时新增一份本地状态。多份未绑定身份时用选择器指定要接续的那份。 | 创建线上资源壳并写入 `resourceId`；只记录产物路径，不上传、不发版、不上架。 |
| `bind <资源ID或username/name> [--artifact <路径>] [--resource <selector>] [--force --yes]` | 线上已有且属于当前账号的资源，需要接入本地工程。 | 从平台读取身份，写入或接续一份 `N.json`；不拉版本、不上传。 |
| `status [--resource <selector>]` | 确认本地身份、工作稿有无与线上 latest；不显示上下架或完整展示资料。 | 只读。 |
| `resource list` | 诊断当前工程身份、单资源工作稿、重复/孤儿状态和未决记录。 | 只读本地；不修复、不查“我的线上资源”，也不诊断完整合集表单稿。 |
| `resource sync [--resource <selector>] [--json]` | 网页或其它机器改过标题，需要刷新本地标题。 | 无选择器同步当前环境全部已绑定单资源，否则只同步一份。JSON逐项报告；部分/全请求失败仍返回完整批次且退出1，前置/事务失败走普通错误。见[管理教程](./08-资源管理.md#同步本地标题)。 |
| `resource recover` | 上次版本提交因网络或中断留下未决记录。 | `prepared` 显示尚未发送；`sending` 只读核验目标版本与文件 SHA；不重发。 |
| `resource recover --apply --yes` | `resource recover`显示“尚未发送”或“已确认”。 | 前者只清记录留稿；后者清本次记录，摘要证明稿未变才一起删稿，否则留稿提示。未确认或SHA不同拒绝。 |
| `version set --artifact <路径> [--resource <selector>]` | 文件改名、构建目录从 `dist` 变成 `build`，只想更新默认路径。 | 只改选中 `N.json.filePath`；不上传、不提交。 |

`--name` 是当前账号命名空间中不可重复、创建后不可改的短标识；`--title` 是可修改且可重复的展示名称。创建后的标题用 `update --title` 修改；本地单资源标题用 `resource sync` 对齐。换绑另一资源必须明确用 `--resource` 指定旧身份，再传 `--force --yes`；被替换身份的旧版本稿会丢弃。重复绑定同一资源不会因此强制丢稿。

## 版本：查看、工作稿与提交

本节每条命令均可加 `[--resource <selector>]`；多资源工程中不传时按上文公共规则选择或停止。

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `version show [--version <已发号>] [--resource <selector>]` | 查看线上已发行版本。 | TTY 未指定版本时选择；`--yes`/非交互默认 latest。指定号必须已发行。只读，不覆盖本地稿；`--json` 的交互菜单走 stderr。 |
| `version show --local [--resource <selector>]` | 查看未提交工作稿。 | 只读；没有工作稿会提示失败。 |
| `version draft pull [--version <已发号>] [--resource <selector>]` | 已有线上版本，基于 latest 或指定版本建立更新稿。 | 写入 `N.version.json`；有旧稿时 TTY 默认不覆盖并确认，脚本须 `--yes`。 |
| `version draft pull --yes [--resource <selector>]` | 明确放弃当前工作稿，重新拉取版本。 | 校验目标线上版本后覆盖工作稿；先打印即将丢失的摘要。 |
| `version draft discard [--yes] [--resource <selector>]` | 明确放弃当前工作稿。 | TTY 显示摘要并默认不删；脚本须 `--yes`。确认后删除选中 `N.version.json`；没有稿时安全退出。 |
| `version draft description --description <文本> [--resource <selector>]` | 修改**更新工作稿**的版本说明。 | 只写工作稿；不发新版本。 |
| `version description [--version <已发号>] [--description <文本>] [--resource <selector>]` | 修改一个**已发布版本**的说明，而不创建新版本。 | TTY 可选版本、输入并确认；回车不改。`--yes`/非交互必须给说明，省略版本用 latest；显式空串清空。只写说明、不写工作稿；读回核对后成功。JSON 为 `{version,description,changed}`。 |
| `version attr add\|set\|rm\|list [--resource <selector>]` | add/rm 维护自定义属性；list 展示自定义及当前 SHA 的系统附加字段/规则；set 按平台格式填写附加值，不接受系统键伪装为自定义项。 | 写操作只改工作稿；`list` 只读查询。 |
| `version attr review [--resource <selector>]` | 查看文件分析变化后待复核的系统附加属性。 | 只读；有待复核项时不能提交。 |
| `version attr review discard <key> [--yes] [--resource <selector>]` | 确认丢弃一项待复核系统附加属性。 | 仅影响该工作稿；同 key 后续出现且值通过当前规则才自动恢复，无需丢弃。 |
| `version option add\|set\|rm\|list [--resource <selector>]` | 维护工作稿的可选配置。 | add / set 只在资源类型允许时可用；rm 可清理遗留项；提交前再核类型。 |
| `version dep add\|range\|rm\|list [--resource <selector>]` | 维护工作稿中的依赖及版本范围。 | add/range 先确认当前资源的合同，缺合同时选择策略签约；不支付。rm 不解约。 |
| `create-version --prepare [--artifact <路径>] [--resource <selector>]` | 尚无已发版本时上传分析并建立首版工作稿。 | 写工作稿，不提交线上版本。 |
| `create-version --yes [--artifact <路径>] [--resource <selector>]` | 尚无已发版本时提交固定的`1.0.0`。 | 上传并提交首版、回写有效产物路径；成功只删本次未变稿，后来变稿留存提示。结果未知走`resource recover`。 |
| `create-version --reset ... [--resource <selector>]` | 首版工作稿确认不要了，直接从空表重新走本次命令。 | 先校验路由和产物；有稿时确认后才丢弃。确认后的后续失败不会恢复旧稿。 |
| `update-version --version <新号> --yes [--artifact <路径>] [--resource <selector>]` | 已有线上版本，指定后续版本号并提交。 | 上传并提交新版本；成功只删本次未变稿，后来变稿留存提示。结果未知走`resource recover`。 |
| `update-version --bump patch\|minor\|major --yes [--resource <selector>]` | 已有线上版本，按 latest 自动计算新版本号。 | 与上条相同；不能和 `--version` 同用。 |
| `update-version --reuse-version <已发号> ... [--resource <selector>]` | 工作稿的底不是当前 latest，且明确以该已发号为底提交。 | 只改变本次提交认可的底；工作稿来源必须匹配。 |
| `update-version --reset ... [--resource <selector>]` | 当前更新稿确认不要了，要丢掉并按本次指定底重新拉取后继续。 | 先校验路由、新号和产物；有稿时确认后才删除。确认后的后续失败不会恢复旧稿。 |

首版只能使用 `create-version`，已有版本只能使用 `update-version`。`--artifact` 在发行命令中是本次上传的真实文件/构建目录；普通资源必须是文件，主题/插件可以是文件或非空构建目录：目录临时压缩，文件（包括 zip）直接上传。不要把 `version draft description` 与 `version description` 混用：前者改未提交更新稿，后者改已发布版本。

属性、配置和依赖编辑以工作稿为目标。没有工作稿时，已有线上版本先 `version draft pull`；首版先 `create-version --prepare`。依赖 add/range 先核验当前资源的合同，已签未支付可继续；无合同时交互选策略，脚本给 `--policy <ID> --yes`。提交版本也检查所有依赖已有生效合同，避免手改 JSON 绕过；提交不会代签或支付。`dep sign` 只补签已有声明，不创建或改稿。

表单子命令的具体输入形状（各命令另补同一选择器、工程与环境）：

| 子命令 | 输入 |
|---|---|
| `version attr add\|set "一行式"` | 例如 `"名称=作者 键=author 值=张三"`；set 按已有 key 修改。 |
| `version attr rm <key>` | 自定义属性键。 |
| `version option add\|set "一行式"` | 例如 `"名称=主题 键=theme 方式=文本 默认=dark"`。完整选项输入见[版本工作稿](./06-版本工作稿.md)。 |
| `version option rm <key>` | 配置键。 |
| `version dep add <资源ID或完整标识> [--range <semver范围>] [--policy <ID>]` | 校验目标、范围与循环后确认合同并写稿；已有依赖省略范围时保留原范围。 |
| `version dep range <资源ID> [--range <semver范围>] [--policy <ID>]` | 只修改已有依赖，TTY未给范围可选择已发版本及固定/兼容或自定义范围；非交互必须显式range，确认合同后写稿。 |
| `version dep sign <资源ID或完整标识> [--policy <ID>]` | 给稿中已有声明补签；没有稿则核对已发行版本，不修改稿。脚本签约须 `--yes`。 |
| `version dep recover [operationId] [--apply --yes]` | 默认只读核验签约记录；显式 apply 仅清理精确确认的记录，始终保留稿。 |
| `version dep rm <资源ID>` | 删除本地依赖声明，不撤销已产生的合约。 |

add/set 一行式包含完整输入时可加 `--yes` 跳过预览确认；不能靠 `--yes` 自动生成缺失字段。

## 展示信息、策略与上下架

本节每条命令均可加 `[--resource <selector>]`；多资源工程中不传时按上文公共规则选择或停止。

| 命令 | 何时使用 | 影响 |
|---|---|---|
| `update [--title] [--intro] [--cover] [--tags] --yes [--resource <selector>]` | 只修改资源展示信息。 | 更新线上 listing；不发版、不改标识、不上下架。未传字段不改；`--intro ""`、`--tags ""` 清空对应字段；`--cover` 只能给工程内 JPG/PNG/静态 GIF（≤5MB），CLI 上传后写 URL，暂不支持清空封面。 |
| `policy list [--resource <selector>]` | 查看当前资源的全部授权策略；页头显示根到叶的资源类型链。 | 只读，不分页。 |
| `policy template list [--json] [--resource <selector>]` | TTY 每页 20 条，可翻页并直接选择模板、编辑参数、预览和创建；非 TTY 默认只打印首页；`--json` 一次输出全部 `normal` 模板及参数、指纹。当前请求服务端全量快照，再按编译主体筛选。 | 只读直到用户在 TTY 预览并确认创建；`--json` 始终只读。 |
| `policy template info <templateId> [--json] [--resource <selector>]` | 查看模板全文、参数编号、默认值、选项和非交互命令骨架；`--json` 只输出这一条的机器描述。 | 只读。 |
| `policy template apply <templateId> [--resource <selector>]` | TTY 逐项编辑、预览译文后创建；非交互或显式传参数时须同时给 `--template-fingerprint <值> --name <策略名> --param "编号=值"`（每个槽位各一项）和 `--yes`。详见[单资源授权策略](./07-单资源授权策略.md)。 | 平台编译并翻译后新增、启用一条策略；不付款、不上架。 |
| `policy set --id <策略ID> --on` 或 `--off` | 二选一启用或停用当前资源的一条策略，可加 `--resource <selector>`。 | 更新线上策略状态；已上架资源不能停用到零条启用策略。 |
| `validate --for online [--resource <selector>]` | 上架前预检版本和策略条件。 | 只读。 |
| `online [--resource <selector>]` | 资源有已发版本和至少一条启用策略后上架。 | 更新线上可用状态。 |
| `offline [--resource <selector>]` | 暂停线上可用状态。 | 只下架，不删除版本、策略、资源或本地文件。 |

## 脚本最小安全模板

下面仅适用于已绑定且已有线上版本的资源，不是首次发行模板。统一使用同一资源 ID；先只读核对目标、latest、本地工作稿有无和默认产物路径：

```powershell
freelog-cli status --cwd <工程> --resource id:<资源ID> --env dev
freelog-cli version show --cwd <工程> --resource id:<资源ID> --env dev
```

确认没有要保留的旧稿、本次新文件已经存在，才建立更新稿并提交。替换占位符后，将**整个脚本块**作为一个单元执行（或保存为 `.ps1` 执行）；每条外部命令后显式检查退出码。不要逐行跳过检查，也不要用捕获后继续的逻辑吞掉错误：

```powershell
& {
    freelog-cli version draft pull --cwd <工程> --resource id:<资源ID> --env dev
    if ($LASTEXITCODE -ne 0) { throw "拉取失败，停止提交；退出码：$LASTEXITCODE" }

    freelog-cli update-version --cwd <工程> --resource id:<资源ID> --artifact video-v2.mp4 --bump patch --yes --env dev
    if ($LASTEXITCODE -ne 0) { throw "提交未确认成功，停止后续操作并核实结果；退出码：$LASTEXITCODE" }

    freelog-cli version show --cwd <工程> --resource id:<资源ID> --env dev
    if ($LASTEXITCODE -ne 0) { throw "查询失败，不代表提交失败；退出码：$LASTEXITCODE" }
}
```

pull 未加 --yes，非交互遇到已有稿会停止而不是覆盖；上述退出码检查确保前一步失败时不继续 update-version。这里是 PowerShell 语法，macOS 的 bash/zsh 脚本需使用其对应的失败停止机制，不能直接粘贴此块。需要保留或编辑稿时改走[更新完整教程](./04-日常路径.md#接入已有资源并发布新版本)。

需要机器可读错误时追加 `--json`。脚本优先用 `id:`、完整 `name:` 或 `file:N.json`；标题只作展示，不能作为选择器，也不要依赖交互式选择。

### AI自动化中的参数保真

Windows的`.cmd`包装器、PowerShell及bash/zsh有各自的引号规则。输入的空格、`^`、`|`到达CLI前就可能被shell处理，CLI不能恢复已经丢失的字符。Node脚本建议直接执行已安装包的`dist/bin/index.js`，使用参数数组并保持`shell:false`，不拼接shell命令。例如将下面保存为`.mjs`，替换目标和范围后在已登录工程执行，并通过第一个脚本参数提供CLI入口的绝对路径：

```javascript
import { spawnSync } from 'node:child_process';
const cliEntry = process.argv[2];
if (!cliEntry) throw new Error('需要已安装CLI的dist/bin/index.js绝对路径');
const result = spawnSync(process.execPath, [
  cliEntry, 'version', 'dep', 'add', 'username/resource-name',
  '--range', '^1.0.0 || ^2.0.0', '--resource', 'id:<资源ID>', '--env', 'dev',
], { shell: false, stdio: 'inherit' });
process.exitCode = result.error || result.signal ? 1 : result.status ?? 1;
```

这只减少shell转义层，不表示Windows隐藏输入或Ctrl+C退出的问题已经解决。连续属性命令也各自保存，后一步失败不会撤销前面的成功；先查看工作稿再决定如何继续，不能整体盲重试。
