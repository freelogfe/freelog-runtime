# 故障恢复与常见报错

::: info CLI 同步文档
本页自动同步自 CLI 仓库使用手册。先核对已安装版本与本页适用范围；Node.js 22.14+ 是 CLI 自身要求，不是运行时对子应用的要求。来源、发布状态及已知限制见[版本说明](/about)。
:::


先确认环境、工程和目标，再判断失败发生在哪一步。网络报错不等于平台没有成功；不要立即重发。需要机器可读错误时加 `--json`；参数解析也遵守该约定，命令参数见[命令参考](./11-命令参考.md)。

示例使用`--env dev`；多资源工程同时传`--resource id:<资源ID>`。正常报错一般保留未提交稿；发行成功清理本次未变稿，后来改变的稿保留并提示。明确覆盖、丢弃、reset或换绑仍可能丢弃内容。不能承诺“任何失败都能恢复旧稿”。

## 先看失败原因，再决定下一步

后端明确返回失败时，CLI展示后端的`msg`，例如“添加策略失败：请先添加结算方式”。不会把正常原因统一改成“操作失败”或“结果未知”；已知词表key使用平台中文，没有翻译的正常英文原因保留原文。密码、令牌、验证码携值及错误堆栈不会原样输出。

| 实际情况 | 如何理解和操作 |
|---|---|
| 平台明确拒绝并给出原因 | 按后端提示处理，例如补结算方式、核对权限或修改参数；CLI不会自动重试 |
| 精确资源详情查询未找到目标 | `RESOURCE_NOT_FOUND`，提示“资源不存在，请检查资源ID”，退出4；仅适用于该接口的成功信封data:null。HTTP404属于请求错误，可能由路径中的ID未正确取得造成，不作为未创建或可创建的依据 |
| `exhibit add` 显式传入空白 `--name` | `EXHIBIT_NAME_INVALID`，退出2；请提供有效授权标识，不会自动改用来源默认标识 |
| 授权交互时按 Ctrl+C | `CANCELLED`，退出8；若此前已发送创建请求而结果不确定，仍按结果未知核对节点展品 |
| SDK 明确返回登录失效业务码30 | `PLATFORM_UNAUTHORIZED`，退出3；重新登录后核对目标。仅有模糊 HTTP 403 的已发送写入不能据此断定未创建 |
| 断网、超时，或平台没有给出有效说明 | CLI说明连接/读取/响应问题；先判断是否已经提交，不能只因失败就重复写入 |
| 已发送修改，但结果尚未确认 | 保留原有结果未知码、工作稿和未决记录（该命令有记录时）；按本页对应恢复入口核验，不自动重发 |
| 线上已成功，本地收尾失败 | 只处理本地收尾，不重新发行或创建 |

一次操作可以有多步：封面已经上传但资料提交被拒绝时，上传对象可能保留；失败不等于全部步骤从未发生。失败响应里的空列表不是“没有模板/合同/资源”，CLI会停止，不拿其中残留数据继续操作。

实际可用范围与安装来源统一见[版本选择](./00-版本选择与AI代办.md)。

## 验证码登录失败

如果账号存在但未绑定手机号或邮箱，发码会提示“当前账号未绑定手机号或邮箱，请使用账号密码登录”。请改用默认密码登录：`freelog-cli login --env dev`，或先在用户中心绑定联系方式，再使用验证码登录；单纯等待重试不能补齐联系方式。该失败不会进入短信码输入或保存登录态。

验证码登录在取图前检查格式与注册状态：`LOGIN_PHONE_INVALID`表示输入不符合手机号规则且该数字用户名不存在；`LOGIN_EMAIL_INVALID`表示邮箱格式有误；`LOGIN_ACCOUNT_NOT_FOUND`表示平台明确查不到该账号。修正登录名或先注册后重新执行 `login --method code`。`LOGIN_ACCOUNT_LOOKUP_FAILED`表示查询暂时失败或结果无法核实，不等于未注册。这些情况均不取图、发码或保存登录。后续发码/认证仍保留明确、安全的业务拒绝原因，不自动注册或重发；不要向聊天或日志提供验证码、密码和Cookie。

## 参数解析错误和 JSON 输出

实际`--json`模式下，参数解析和业务失败均向stdout输出一份JSON，不重复写stderr；help和版本仍是文本。成功业务数据按各命令定义，不以“能解析JSON”判断业务完成。

| 情况 | 输出与下一步 |
|---|---|
| 缺参数值、未知选项等命令语法错误 | 退出2，stdout为错误JSON，category=input；先修命令，不会发送业务请求 |
| 命令已解析，业务检查或执行失败 | 按category、code及该命令的恢复说明处理；具名批量保留明细并在error提供分类 |
| --help、--cli-version | 正常文本，退出 0；用于查看帮助/版本，不是业务 JSON |

例如以下写法都缺少工作目录值，会在执行业务前停止；`type info` 也遵守相同规则：

```powershell
freelog-cli node list --json --env dev --cwd
freelog-cli node list --cwd --json --env dev
freelog-cli type info RT005001 --json --env dev --cwd
```

最后一条命令退出2，stderr为空，stdout为以下JSON。补上实际目录（例如 `--cwd "E:\我的 工程"`）后再执行：

```json
{"code":"CLI_OPTION_VALUE_MISSING","message":"选项缺少必填值，请使用 --help 查看参数说明","category":"input","outcome":"error"}
```

### 退出码与处理

先看中文含义决定下一步；AI或脚本使用退出码和JSON字段判断，不根据中文提示猜测结果。

| 退出码 | 中文含义 | JSON分类（category） | 下一步 |
|---|---|---|---|
| 0 | 正常完成 | — | 读取对应命令的结果，核对是否达成本次目标 |
| 1 | 一般失败（未分类） | `other` | 按code/message核实原因；不能据此认定远端没有执行 |
| 2 | 输入错误 | `input` | 修正参数或输入 |
| 3 | 登录、权限或授权问题 | `auth` | 按提示处理登录、权限或所需授权 |
| 4 | 目标不存在 | `not_found` | 检查明确的目标ID或标识 |
| 5 | 操作被明确拒绝 | `rejected` | 按具体拒绝原因处理 |
| 6 | 结果未知，需核实 | `result_unknown` | outcome=unknown，先用原恢复/查询入口核验，不直接重发 |
| 7 | 处理中或待收尾 | `processing` | outcome=pending，继续原操作的查询或收尾，不重新提交 |
| 8 | 用户取消 | `cancelled` | outcome=cancelled，停止当前流程；取消不表示已回滚前序成功步骤 |

`category`表示问题类别；`outcome`区分错误（error）、结果未知（unknown）、待处理（pending）和取消（cancelled）。中文含义只用于解释，JSON仍使用表内英文取值。

成功结果按各命令定义，不要求统一返回category/outcome；表中的“—”不是JSON字段值。**退出0只表示命令正常完成。**例如授权查询退出0但isAuth=false，表示查到了“尚未获得授权”，不是已经授权；准备工作稿成功也不等于版本已发行。结果未知和处理中应按各自入口核实，不直接当作失败重发。

普通错误包含`code/message/category/outcome`。部分完成结果保留命令原有`status/outcome`及成功/失败明细，共同错误位于`error`；任一已知子项结果未知时退出6，不能整批重发。未分类错误不按消息猜结果。授权模块自有结果及命令已明确的局部非零业务结果仍按各命令说明读取。

--env、--cwd、--resource 出现时都必须填写值，不能把后面的选项当作值。带空格的目录加引号，例如 --cwd "E:\我的 工程"；确实需要以短横线开头的字面值时用等号，例如 --cwd=--json 表示名为 --json 的相对目录。独立 -- 表示选项结束，后面的内容作为位置参数；它不能代替前一个选项缺失的值。

## 登录、路径和选择

| 情况 | 下一步 |
|---|---|
| `NODE_VERSION_UNSUPPORTED` | 当前Node版本低于22.14.0。先升级到受支持的Node22或24 LTS，再重新打开终端执行命令；此拒绝发生在登录、读取凭据和执行业务前。 |
| prod 平台调用被拦截 | 当前prod的读取和写入均不可用；明确传 `--env dev` 或 `test`，不要依赖缺省环境。 |
| 请先 login、凭据损坏或环境不符 | 检查 `--cwd` 和最近的账号选择器；必要时在选择器所在目录 logout 后重新 login。不会静默回退到全局账号。 |
| 当前目标已有凭据 | 在同一登录目标先 logout，再 login；资源身份和工作稿不会因此删除。 |
| `LOGIN_SELECTOR_SAVE_UNCONFIRMED` | 系统凭据已保存、选择器写入未确认。核对所示路径，存在时先在该目标 logout（全局目标加 --global），处理磁盘权限／空间后再 login。不要手动删除可能共享的系统凭据。 |
| 模板初始化拒绝非空目录 | `init theme/widget` 不合并已有源码。选新目录；已有工程改走通用 init 或直接 create。仅已有登录目录时的允许条件见[主题与插件](./05-主题与插件.md)。 |
| `INIT_COMMIT_FAILED` | 工程文件提交失败，本次移动已回滚。核对目标目录和权限后重试，不需要删除原有 auth。 |
| `INIT_ROLLBACK_INCOMPLETE` | 自动回滚无法安全完成。先备份并核对错误中给出的目标和暂存目录；不要直接删除目录或反复 init，未知/已修改内容被保留，需要先明确整理。 |
| `TEMPLATE_INVALID` / `TEMPLATE_DOWNLOAD_FAILED` / `TEMPLATE_EXTRACT_FAILED` | 模板校验、下载或解包失败，不继续写身份。检查网络、npm/tar是否可用及当前模板；CLI不自动换模板、不执行模板脚本。Windows需要可定位的npm JS入口。 |
| 类型不可用、不是最终叶子 | 用 `type search/list/info` 查当前可用最终叶子；脚本传精确 code，不传名称或父节点。 |
| 模板主题/插件类型冲突 | 已有模板身份使用固定类型，移除冲突的 `--type`。 |
| 空的 `--resource ""` | 不代表默认资源或同步全部，会直接拒绝。单份操作请填完整选择器；需要默认选择或批量标题同步时，省略整个`--resource`参数。 |
| `BIND_TARGET_MISMATCH` | 详情返回的资源与请求ID或完整标识不一致，本地身份和稿不会被换绑。核对目标；不要用`--force`绕过，仍失败时由维护者核对接口。 |
| `VERSION_AUTH_CONFIG_UNSUPPORTED` | 当前资源/所选底稿已有上抛或授权排除配置，或资源详情缺少必需上抛名单；本期请到Console维护。写前发现时保留旧稿且不上传；途中才发生变化则停止后续提交，保留当前已准备稿，不回滚先前上传。不要用`--yes`、reset或手改空数组绕过。 |
| `BIND_LOCAL_STATE_CHANGED` | 读取详情期间本地身份被修改，CLI保留当前文件并停止。先核对当前身份和稿，再重新决定绑定目标。 |
| 多份状态，无法确定目标 | 用 `id:`、完整 `name:`、`artifact:` 或 `file:N.json` 明确选择；标题不能定位资源。 |
| 产物不存在、为空或路径越界 | 恢复工程内真实文件或构建内容。普通资源不能传目录；主题/插件登记空目录可以，发行空目录不可以。 |
| 路径与另一资源重复或嵌套 | 为每份单资源使用独立产物；不要让一个构建目录吞入其它资源的文件。 |

登录和账号继承详见[环境与凭据](./02-环境与凭据.md)。

## 工作稿与发行

| 情况 | 下一步 |
|---|---|
| 首版/更新入口用反了 | 无已发版本用 `create-version`；有已发版本用 `version draft pull` 后 `update-version`。 |
| 更新提交提示必须 --yes | 当前更新入口要求显式 `--yes`，同时给 `--version` 或 `--bump`。 |
| 工作稿来源不是当前 latest | 先看 `version show --local`；通常以 `version draft pull --yes` 重建。继续旧底须明确匹配的 `--reuse-version`，新号仍大于当前 latest。 |
| 要覆盖或丢弃，却缺确认 | 先检查摘要；交互终端确认，脚本明确带 `--yes`。 |
| 类型字段定义变化后有待复核属性 | version attr review查看；恢复合法字段值或明确review discard确认丢弃，不能忽略后提交。 |
| 当前类型不支持可选配置 | 以类型详情的能力为准；不要新增或修改配置。历史配置可用 `version option rm <key>` 清理。 |
| `TYPE_RESPONSE_INVALID` | 类型服务请求失败、业务码异常或返回结构不完整。本次不会据此新建本地身份或资源壳；确认类型服务恢复后重试，不要把失败当作“没有匹配类型”。 |
| 依赖已声明，但运行时仍提示无授权 | 声明或已有合同不等于当前访问获授权。到网页按正确资源、合集或节点身份完成支付/其它履约，再核授权；当前CLI不发新支付。见[支付说明](./授权与支付/支付与恢复.md)，个人合同不能替代。 |
| 依赖的policy、dep sign、存储或节点展品命令不识别 | 先核cli-version、help和[安装来源](./00-版本选择与AI代办.md)。依赖声明add/range不接受policy、不处理授权，sign只给网页路径；作者策略启停用id，展品策略启停用policy-id，不能混用。 |
| 合集单品缺少上游合同 | 到网页按当前合集身份办理上游签约，再回CLI添加或应用已有合同；本期`--sign-policy`不执行新签，不能用个人购买替代。旧未知结果先用操作ID恢复，不重发。 |
| 上架缺版本或启用策略 | 完成版本发行与自身策略创建后再 online；依赖签约不能代替自身策略。 |
| 改说明没有产生新版本 | `version description` 改已发版本；下一版说明用更新稿的 `version draft description`。 |
| `CLI_UNEXPECTED_ERROR` | CLI 隐藏了可能含凭据的底层异常，不输出原始请求或错误栈。如刚执行写操作，先按下面的恢复流程核对实际结果，不要直接重复提交；不要为排查粘贴 token、cookie 或凭据库内容。 |
| `RESOURCE_NOT_FOUND` | 资源详情查询成功且data:null，未查询到资源，未继续发送修改。HTTP404按`PLATFORM_HTTP_NOT_FOUND`排查接口路径和标识；缺失、空白或字面量undefined/null的资源标识应在请求前被拒绝。 |
| `RESOURCE_FROZEN` | 初次读取发现资源已冻结，拒绝修改。资料修改和上下架在确认后直接提交，由后端裁决当前可写性；已上传图片不自动删除。 |
| `PLATFORM_REQUEST_REJECTED`及各业务`*_REJECTED` | 平台明确拒绝本次请求，显示安全后端msg；缺失或不能安全显示时才使用CLI说明。若仍提示操作ID/recover，按提示核验记录，不手动删除或重复请求。 |
| `PLATFORM_UNAUTHORIZED` / `PLATFORM_FORBIDDEN` | 分别为登录失效、平台拒绝访问。先检查登录账号及目标权限，不把无权限说成资源不存在。 |
| `PLATFORM_HTTP_NOT_FOUND` / `PLATFORM_RATE_LIMITED` / `PLATFORM_SERVICE_ERROR` | 分别为接口或目标不存在、请求频繁、平台服务异常。按提示检查；若写入已发出，先核对实际结果。 |
| `PLATFORM_READ_FAILED` | 写入前读取信息失败或超时，未继续修改。它与已经发送写入后的结果未知不同。 |
| `PLATFORM_RESPONSE_INVALID` | 平台对象响应没有证明请求成功，CLI停止消费其中的业务字段。确认平台恢复后再查询；若提示结果未知，先核验已发送操作，不重复写入。 |
| `POLICY_TEMPLATE_COMPILE_FAILED` / `POLICY_TEMPLATE_TRANSLATION_FAILED` | 编译或翻译失败，本次尚未创建策略。平台有安全业务说明时会显示；未知请求仅提示“平台请求失败”，不附原始请求信息。保留模板 ID 便于排查；修正参数或确认平台恢复后再试，CLI 不自动替换其它模板。 |

`--reset` 先做确定性校验，再确认丢弃旧稿。确认后的上传、网络或提交失败不会把旧稿恢复回来。明确换绑另一资源也会丢弃被替换身份的工作稿。

## 中断与结果未知：分开处理

### 单资源版本提交

```powershell
freelog-cli resource recover --env dev
```

该命令根据工程内未决记录固定目标，只读核验，不重发。读清结果后：

```powershell
freelog-cli resource recover --apply --yes --env dev
```

- `prepared`：还未允许发送 POST，只清未决记录，保留工作稿。
- `sending`：只有版本详情的资源ID、版本号与SHA1都和记录精确一致，才清本次未决记录。当前稿还与发送时的字节摘要相同才一起删除；稿已变化或旧v1/v2记录无法证明未变时，保留整份稿并提示。无稿时不会重建。
- 查不到、详情缺字段、返回另一资源/版本、SHA1 不同或仍不确定：不会清理；保留现场，继续核实，不猜成功或失败。

不要手动删除 `.pending-operation.json` 后重发。

`SUBMIT_DRAFT_CHANGED`表示提交前校验期间稿被改过：本次没有POST，也没有新建未决记录；先检查当前稿再重新提交。若已提示“版本已提交，当前稿已保留”，不要重发同一版本；先读线上结果，再决定保留稿如何用于下一版。仅空白变化也按新字节保留。

明确 HTTP 5xx 即使附有可读报错，也不能证明版本没有创建成功；CLI 会保留稿和未决记录，按上面的流程核验，不自动重试。

### 策略创建

```powershell
freelog-cli policy list --resource id:<资源ID> --env dev
```

合集用对应的 `collection policy list`。查名称、启用状态和线上结果，再决定后续动作；不套用 `resource recover`，也不因创建报错立刻重复申请。

### 单资源资料与上下架

`UPDATE_RESULT_UNKNOWN` / `SHELF_RESULT_UNKNOWN`表示写入或其后的核验未能完成；`UPDATE_VERIFY_FAILED` / `SHELF_VERIFY_FAILED`表示实际读回与目标不一致。先在网页核对指定资源的资料/状态，保留工程，不重发、不用resource recover清理。`UPDATE_LOCAL_CACHE_FAILED`则已证明线上资料成功，只是本地标题同步失败，使用`resource sync --resource id:<资源ID> --env dev`修复缓存，不重复改线上。

非TTY写入需要`--yes`；取消或未确认不会上传封面/PUT。幂等结果changed=false不是失败，表示当前已满足请求或无修改项。完整输出和操作说明见[资料与上下架管理](./08-资源管理.md)。

### 合集发行与其它写操作

先区分未决记录：发行使用本地intent；单品签约、应用或添加使用操作ID。省略操作ID时也会列出本合集相关单品未决摘要。

**核验发行intent：**

```powershell
freelog-cli collection publish resume --resource id:<合集ID> --env dev
```

默认只读诊断，不自动清理或重发。诊断已确认后，可用同命令加`--apply --yes`收尾；它会重新核验，后来修改或新建的当前稿仍保留。明确拒绝且完整旧快照未变时，收尾只清已拒绝记录，不表示发布成功。

**核验某条单品操作：**

```powershell
freelog-cli collection publish resume <操作ID> --resource id:<合集ID> --env dev
```

先读结果；已精确确认完成、未发送或明确拒绝且旧态未变时，再用同命令加`--apply --yes`收尾。不重签、不再次添加，也不发后续步骤；未确认时保留记录。

这个恢复入口不处理合集资料、策略等写入，也不是所有目录编辑的通用恢复器；这些操作通过各自只读查询核对结果。完整的记录范围、清理条件和稿保护见[合集恢复说明](./合集/02-发行后管理与边界.md#发布、未知结果和基线变化)。

## 本地状态损坏、锁和事务

创建时遇到`CREATE_NAME_SLASH`，请把`--name alice/demo`改为`--name demo`，用户名由当前账号补齐；拒绝时尚未发送平台请求。`CREATE_LOOKUP_FAILED`表示未能可靠查明资源是否存在，CLI不会继续创建；先检查账号和网络。`CREATE_FAILED`可能发生在创建请求已经发送之后（包括响应缺少有效ID），应先在线上核对是否已生成授权条目，确认后再决定bind或后续操作，避免直接重发创建。bind的`BIND_INFO_INVALID`表示详情响应失败或无效，不会登记本地身份；核对目标及网络后再试。

先运行不依赖正常业务解析的本地诊断：

```powershell
freelog-cli resource list --env dev
```

它会报告身份、版本稿、重复状态、孤儿稿和未决记录等问题，不会修复或删除文件。

若显示“本地状态读取失败”，这是隐藏了未知底层异常，不代表文件已删除或修复；保留现场，检查对应文件和访问权限，不把凭据内容贴进报告。

- 损坏或错配工作稿可能连 `draft discard/pull` 都无法通过前置校验，不能承诺用同一条命令自动修复。
- 先备份整个 `.freelog/`，保留文件名、内容及错误信息。存在未决提交或事务时先查明远端事实，不能只删身份或稿掩盖问题。
- 确认不要且没有未决操作关联的工作内容，应在保留备份后单独处理；恢复线上身份使用 bind，不把旧 JSON 或自造字段当成受支持导入协议。
- `.lock` 是写锁。先确认没有其它 CLI 在写同一工程；不要删除正在使用的锁。
- `.txn.json` 是跨文件事务。下一次持锁写操作会尝试前滚恢复；持续失败时保留现场，不手动拆开修改事务。
- 凭据选择器不是可移植登录文件，不复制或手改；不要把秘密放进状态 JSON。

本地文件各自的含义见[本地文件参考](./10-本地文件参考.md)。
