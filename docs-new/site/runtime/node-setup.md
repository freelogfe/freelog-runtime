# 准备真实节点和基础主题

本页的终点是：你拥有一个真实节点，已启用可访问的主题，并取得节点地址。之后才能从节点加载本地主题或调试插件。已有这些条件可直接进入[快速开始](/runtime/quickstart)。

节点创建可以通过 Console 或 CLI 0.6.0+ 完成，见[节点创建操作](/cli/节点与展品/#需要新节点时)。主题激活/切换当前仍按下文使用 Console；CLI的展品展示版本切换不是切换节点主题。

## 开始前由用户确认

- 使用哪个环境、哪个账号，是否已有本人管理的节点。
- 是否允许创建节点或切换现有节点的主题。切换会改变该节点的访问页面，不能由 Agent 为了调试擅自切换他人的使用入口。
- 登录及平台要求的必要认证由用户本人完成。Agent 可以读取文档、普通查询、准备字段、构建项目；经用户明确授权后，也可以通过浏览器协助操作节点页面。

Console 的具体显示文字可能随语言和部署调整；下文按页面功能定位，不提供未经确认的直达 URL，也不要求手工请求平台 API。

## 1. 已有节点：先检查，避免重复创建

进入对应环境的 Console，从本人节点列表打开目标节点管理页。核对节点标题、标识、地址及所有者，进入主题管理区域。

如果已有可用且启用的主题，先访问节点确认页面能正常打开，记录节点地址，再继续[本地主题开发](/runtime/quickstart)。不必为了新工程再创建节点或重新发行一个基础主题。

## 2. 没有节点：创建真实节点

Console 的全局创建菜单提供节点创建入口。打开节点创建页，填写：

每人最多3个节点，先检查已有节点再决定是否新建。Agent需要取得用户对具体账号、环境和节点信息的确认，不为调试自行消耗名额。使用CLI 0.6.0+时，创建有专用确认，通用`--yes`不能代替；操作和未知结果恢复见[CLI教程](/cli/节点与展品/#需要新节点时)。

| 字段 | 填什么 | 确认什么 |
| --- | --- | --- |
| 节点标题 | 用户看到的名称 | 与当前用途相符，通过页面校验 |
| 节点标识 | 授权系统中的节点标识 | 页面可能归一化输入；核对最终值，创建后不可更改 |
| 节点地址 | 平台域名后缀之前的部分 | 按页面规则和重复检查结果填写，使用页面实际展示的环境后缀 |

不要把节点标识、地址和资源标识当成同一个字段。等待页面格式及重名检查完成，核对摘要后提交一次。

**成功信号**：创建成功页面或本人节点列表出现该节点，节点管理页中的标题、标识和地址与预期一致。只看到按钮点击完成不算创建成功；请求结果不明确时先查节点列表，不重复提交。

## 3. 尚无主题：使用推荐或开发基础主题

节点创建后的主题设置页，以及没有主题时的主题管理区域，提供推荐主题。页面还提供开发主题入口，可选择平台提供的基础主题用于开发。

1. 查看当前页面实际列出的主题和来源资源；没有合适主题时可通过页面浏览市场主题。
2. 核对所需授权条件，按页面流程选择并确认激活。开发基础主题也来自平台资源，不是本地工程自动生成的节点。
3. 需要支付时，在 Console 完成支付及必要认证。CLI 当前暂不执行支付；未付款或其他条件未满足时，不把签约成功当作已有对应授权。
4. 返回主题管理，确认目标主题显示为已启用的主题，核对展示版本；再访问节点地址。

若已有主题列表，选择目标主题的激活操作；替换当前主题时先核对确认提示。授权告警应先按提示处理，不能以本地开发参数绕过。

**成功信号**：主题管理显示目标主题处于启用状态，节点页面可以加载它。基础主题可能只提供很少内容；关键是节点运行时和主题能够正常加载，没有阻断访问的错误。

## 4. 交给开发阶段的输入

将目标环境、节点地址、基础主题及其展示版本、工程目录交给开发者或 Agent。核对本地工程与基础主题的构建方式，见[版本与兼容](/runtime/compatibility)。随后使用 `dev=<本地 HTTPS 地址>` 加载本地主题；这一步不发布本地版本，也不改变主题管理中的正式资源身份。

节点仍不可访问时，先处理节点状态、主题启用和授权条件，再开始开发调试。具体排查见[运行时问题排查](/runtime/troubleshooting)。
