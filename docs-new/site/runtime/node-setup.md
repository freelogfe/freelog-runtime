# 准备真实节点和基础主题

完成本页后，你将有一个可访问的节点地址，以及该节点已启用主题的展示版本。开始主题开发可直接进入[快速开始](/runtime/quickstart)。准备调试插件时，还需[建立插件挂载位置](/runtime/development#一个全新插件从哪里开始)。

以下步骤使用 Console。CLI 也提供[节点创建、设置和主题激活](/cli/节点与展品/)。

## 开始前由用户确认

- 确认账号和环境，查看已有节点及其启用主题。
- 创建新节点前确认节点信息。使用现有节点时，切换启用主题会改变该节点的访问页面。
- 用户本人完成登录及平台要求的认证。

## 1. 已有节点：先检查，避免重复创建

进入对应环境的 Console，从本人节点列表进入目标节点的「主题管理」。核对节点标题、标识、地址和启用主题的展示版本。

如果已有可用主题，直接打开节点根地址，确认页面正常加载。把节点地址、启用主题和展示版本记录下来，继续[本地主题开发](/runtime/quickstart)。

## 2. 没有节点：创建真实节点

Console 的全局创建菜单提供节点创建入口。每人最多 3 个节点，确认现有节点和名额后填写以下字段。如使用 CLI，按[节点创建步骤](/cli/节点与展品/#需要新节点时)进行专门确认。

| 字段 | 填什么 | 确认什么 |
| --- | --- | --- |
| 节点标题 | 用户看到的名称 | 与当前用途相符，通过页面校验 |
| 节点标识 | 授权系统中的节点标识 | 页面可能归一化输入；核对最终值，创建后不可更改 |
| 节点地址 | 平台域名后缀之前的部分 | 按页面规则和重复检查结果填写，使用页面实际展示的环境后缀 |

等待格式及重名检查完成，核对标题、标识和地址后提交一次。

创建后从本人节点列表打开该节点，核对标题、标识和地址。提交结果不明确时，先从列表查找记录再决定后续操作。

## 3. 尚无主题：使用推荐或开发基础主题

节点创建后的主题设置页，以及没有主题时的主题管理区域，提供推荐主题和开发主题入口。本地 Vite 示例需要启用展示版本的 `bundleTool` 为 `vite`，并核对节点加载的运行时版本。节点依据启用主题的有效 `bundleTool` 选择沙箱。若候选主题没有合适的展示版本，先在本人开发节点启用另一个已核实的 Vite 主题，或[发行基础主题后启用](/runtime/release)。[兼容性与版本](/runtime/compatibility)

1. 查看当前页面实际列出的主题和来源资源；没有合适主题时可通过页面浏览市场主题。
2. 核对所需授权条件，按页面流程选择并确认激活。
3. 需要支付或其他履约时，核对合同乙方为当前节点，由用户本人到对应 Console 授权页面办理。见[签约、支付与授权](/platform/authorization)。
4. 返回「主题管理」，确认该主题已启用并记下展示版本。打开节点根地址，确认主题可以正常加载。

已有主题列表时，选择目标主题的激活操作，根据页面提示处理授权。切换同一个主题的展示版本可在该主题的展品管理中完成。

## 4. 交给开发阶段的输入

交给开发者或 Agent 的信息包括目标环境、节点地址、基础主题及其展示版本、工程目录。正常节点地址验证通过后，按[快速开始](/runtime/quickstart)使用 `dev=<本地 HTTPS 地址>`。节点仍不可访问时，按[运行时问题排查](/runtime/troubleshooting)核对节点状态、启用主题及授权条件。
