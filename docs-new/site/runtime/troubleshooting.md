# 运行时问题排查

先确定失败发生在哪一层：本地服务、子应用生命周期、节点展品、依赖路径，还是授权。不要靠反复发行版本定位一个本地证书问题。

若 CLI 刚进行创建或发行，结果仍未知，先走 [CLI 故障恢复](/cli/09-常见情况与报错)，不要把页面异常当作发行失败。只有确认资源和版本存在后，才继续下面的页面运行排查。

## 本地主题没有出现

按顺序检查：

1. 去掉 `dev`，真实节点是否正常，是否已启用可用主题？
2. 直接打开本地 HTTPS 地址，服务是否在线、证书是否受信任？
3. Network 中是否请求到本地入口、脚本和样式？有没有证书、跨域或混合内容错误？
4. URL 的 `dev` 值是否为实际本地地址？已有参数是否仍保留？
5. `window.mount` 是否被调用，应用容器是否存在，`initFreelogApp()` 是否在挂载时初始化？

`ERR_CERT_AUTHORITY_INVALID` 应先处理本地证书。浏览器要求本地网络访问权限时按浏览器提示授权，不建议关闭浏览器安全机制。线上主题与本地项目打包方式也应匹配，见[兼容性与版本](/runtime/compatibility)。

## SDK 在独立本地页面不可用

SDK 从主应用注入的微前端上下文取得能力。单独打开本地项目不等于在节点中运行；从真实节点的 `dev` 入口验证 SDK。

若旧示例调用 `getSelfDependencyTree()`，改为按当前 API 核对 `getSelfDep()` 的名称和响应结构，不能只更改函数名却继续把完整响应当依赖数组。

## 插件替换没有生效

- 确认主题或父插件已经发起挂载，页面容器实际存在。
- 使用该实例的实际渲染名称，设置 `dev=replace&<渲染名称>-freelog=<本地地址>`。
- 不把资源 ID 或展品 ID 当渲染名称；可在插件内通过 `getSelfWidgetRenderName()`确认。
- 确认本地入口可以访问，且没有丢失原节点页面路由参数。

成功信号是原挂载位置加载本地入口。未出现挂载位置时，应先修复正式挂载链；替换参数不会新增展品或依赖。

## 新增依赖查不到或文件访问失败

先区分 CLI 本地工作稿与节点当前使用版本：

1. CLI 稿内新增依赖，尚未发行：运行时不会自动读到。
2. 已发行，但节点仍使用旧版：在 Console 核对展示版本及实际依赖树。
3. 真实依赖树存在：核对顶层展品、`nid`、父依赖身份及实际请求，不用资源 ID 替换依赖路径。
4. 响应拒绝访问：检查对应主体和链路的授权。个人账号的合约不能替代节点或源资源的授权。

需支付的合约应在 Console 完成付款及必要认证，用户本人处理登录和认证。CLI 当前不执行支付；未完成支付或其他条件时没有对应授权，平台 Console 的支付能力并未因此被禁用。

当前运行时通过展品依赖路径读取内容，未发行的本地依赖声明不能建立这条路径。先完成正式发行和节点版本选择，不通过直接下载或转交CLI凭据替代授权链。

## 属性或配置与预期不同

核对作者发行版本、节点展示版本、节点展品或依赖配置。展品有效值不必等于作者表单默认值；父应用传入业务数据也不是平台属性。

分别记录“期望原始版本值”和“期望展品有效值”，再检查当前 SDK 返回结果。系统附加字段通过平台定义的入口编辑，不要用自定义属性创建同名字段。

## 静态资源、路由或重复挂载异常

检查构建 `base`、静态资源相对路径和沙箱路由接入。Vite 使用模块脚本时，不要把原生 `window.location` 当作子应用自己的路由；按运行时路由能力或框架接入约定处理。

重复打开组件时，检查旧插件控制器是否已卸载，应用是否清理定时器、事件监听和框架根实例。不同渲染实例仍可能共享同一依赖节点配置，不要把实例数量当作新增平台身份。

## 提供可复现证据

需要进一步定位时，记录：节点地址、资源和展示版本、SDK 实际版本、浏览器及操作系统、最少复现步骤、错误时间、Console 堆栈、失败请求 URL 与错误响应。

明确使用正式入口还是 `dev/replace`，以及节点实际使用的版本。分享日志前移除 Cookie、Authorization、登录凭据和带认证用途的链接；不需要提供整个 CLI 状态目录。
