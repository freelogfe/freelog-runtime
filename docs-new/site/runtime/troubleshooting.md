# 运行时问题排查

比较同一个节点页面的正常入口和开发入口。正常入口也失败时，先检查节点、展示版本和授权。只有开发入口失败时，重点查看本地入口、沙箱和应用生命周期。

刚通过 CLI 创建或发行且结果未知时，先按 [CLI 故障恢复](/cli/09-常见情况与报错)核对实际提交结果。

## 本地主题没有出现

按顺序检查：

1. 去掉 `dev`，真实节点是否正常，是否已启用可用主题？
2. 直接打开本地 HTTPS 地址，服务是否在线、证书是否受信任？
3. URL 的 `dev` 值是否为实际的 HTTPS 地址？已有路由参数是否仍保留？
4. Network 中能否看到本地入口，以及该入口引用的脚本和样式？如有证书、跨域或混合内容错误，先处理最先失败的请求。
5. `window.mount` 是否被调用，应用容器是否存在，`initFreelogApp()` 是否在挂载时初始化？

`ERR_CERT_AUTHORITY_INVALID` 指向证书信任问题。浏览器请求本地网络访问权限时，按浏览器提示授权。使用 Vite 调试时，检查当前启用主题的有效 `bundleTool` 是否为 `vite`，它影响节点为主题采用的沙箱。见[兼容性与版本](/runtime/compatibility)。

## 运行时 API 在独立本地页面不可用

主题或插件通过 `initFreelogApp()` 取得节点在挂载时提供的上下文。直接打开本地项目可以检查服务可达性和证书。验证运行时 API 调用时，从真实节点的主题开发或插件替换入口加载本地项目。

迁移旧示例时，按[依赖 API](/runtime/api/widget)核对 `getSelfDep()` 的响应结构。依赖条目位于 `res.data.data`，主题还可从 `getSelfDepForTheme()` 同步读取挂载时取得的依赖数据。

## 插件替换没有生效

- 确认主题或父插件已经发起挂载，页面容器实际存在。
- 使用该实例的实际渲染名称，设置 `dev=replace&<渲染名称>-freelog=<本地地址>`。
- 在插件内通过 `getSelfWidgetRenderName()` 核对实际渲染名称。宿主同时挂载同一插件多次时，确认参数选中要调试的实例。
- 确认本地入口可以访问，且没有丢失原节点页面路由参数。

成功信号是原挂载位置加载本地入口。宿主在开发模式中显式提供的 `widget_entry` 会优先于 URL 替换入口。页面还没有该插件时，按[首次插件路径](/runtime/development#一个全新插件从哪里开始)建立正式挂载。

## 发行后仍加载旧版本

1. 按回执的资源版本号[读回线上版本](/runtime/compatibility#用-cli-填写并读回)，确认文件及系统附加字段。
2. 在节点「主题管理」核对当前启用主题和展示版本。插件另外检查插件展品的展示版本，或实际依赖链解析到的版本。
3. 去掉开发替换参数，刷新节点根地址。在 Network 核对正常文档响应引用的运行时路径，以及实际主题或插件入口请求。具体操作见[节点运行时核验](/runtime/compatibility#核验节点实际加载的运行时)。

## 新增依赖查不到或文件访问失败

先区分 CLI 本地工作稿与节点当前使用版本：

1. CLI 稿内新增依赖，尚未发行：运行时不会自动读到。
2. 已发行，但节点仍使用旧版：在 Console 核对展示版本及实际依赖树。
3. 真实依赖树存在：用实际响应中的顶层展品、`nid` 和父依赖身份核对请求。
4. 响应拒绝访问：核对拒绝发生在资源作者、节点还是访问者的授权关系。

需要支付或其他履约时，由用户本人到对应主体的 Console 页面处理。已有历史订单状态未知时先查询原单。见[签约、支付与授权](/platform/authorization)。

## 属性或配置与预期不同

核对作者发行版本、节点展示版本、节点展品或依赖配置。展品有效值不必等于作者表单默认值；父应用传入业务数据也不是平台属性。

分别记录“期望原始版本值”和“期望展品有效值”，再检查运行时 API 的返回结果。系统附加字段通过平台定义的入口编辑，不要用自定义属性创建同名字段。

## 静态资源、路由或重复挂载异常

检查构建 `base`、静态资源相对路径和沙箱路由接入。Vite 使用模块脚本时，不要把原生 `window.location` 当作子应用自己的路由；按运行时路由能力或框架接入约定处理。

重复打开组件时，检查旧插件控制器是否已卸载，应用是否清理定时器、事件监听和框架根实例。不同渲染实例仍可能共享同一依赖节点配置，不要把实例数量当作新增平台身份。

## 提供可复现证据

进一步定位时，记录节点地址、资源版本、展示版本、实际加载的节点运行时版本、`freelog-runtime` 接入包版本、浏览器及操作系统，以及复现步骤、错误时间、控制台堆栈、失败请求 URL 和错误响应。

明确使用正式入口还是 `dev/replace`，以及节点实际使用的版本。分享日志前移除 Cookie、Authorization、登录凭据和带认证用途的链接；不需要提供整个 CLI 状态目录。
