# 签约、支付与授权：当前边界

本文按CLI 0.8.0当前边界说明操作：节点新展品签约使用内联auth-cli；依赖、已有展品、合集单品上游需要新签约时，以及所有新支付，都到正确主体的浏览器页面办理。CLI保留已有合同校验、历史原单查询及恢复，不生成新订单或二维码。先按[版本选择](/cli/00-版本选择与AI代办)核对实际构建；npm 0.8.0已发布，registry下载、安装及20份手册核验通过。

## 五个结果分别核验

| 结果 | 证明什么 | 不证明什么 |
|---|---|---|
| 已选策略并签约 | 对应主体与授权方形成合同 | 已付款或所有条件已满足 |
| 已添加依赖 | 依赖进入当前待发行版本声明 | 节点或访问者可以读取真实内容 |
| 已发行或已上架 | 平台已保存版本/状态并完成相应核验 | 支付自动完成，或每个访问者都已授权 |
| 原订单交易成功 | 该订单的交易状态为succeeded | 合同授权已生效，或其他主体也已获权 |
| 当前授权通过 | 该访问上下文满足平台授权判断 | 换主体、版本、节点后仍一定有授权 |

**策略要求支付后才获得授权时，须完成所需支付并核验授权。** 若策略有试用或其他路径，按实际条款和结果判断，不能仅凭“付费模板”标签猜测。

## 当前 CLI 怎么处理

1. 依赖声明先核验当前资源或合集的适用合同；缺合同时先到该对象的Console“依赖及其授权”办理。待支付的生效合同可用于部分声明流程，不表示内容已可访问。
2. 新节点展品仅在内联auth-cli已支持的来源自身策略范围内签约创建；必要上抛、已有节点合同复用及已有展品补签转Console，不默选策略或遗漏上游。
3. 需要支付或其它履约时，在正确资源、合集或所属节点的Console页面核对合同、乙方、事件与金额，由用户本人处理。`payment start/qr`只提示暂停，不生成订单或二维码。
4. 用 `payment show <合同ID>` 查询当前账号管理的资源/合集/节点合同信息；用 `payment status <订单ID>` 核对当前账号本地记录指向的历史原单。`--wait`最多五分钟，分别读取 `paymentStatus` 与 `authStatus`；查询退出0不证明付款及授权完成，也不能跟踪没有本地记录的浏览器订单。
5. 超时、传输异常或未知结果先只读核对原合同和原单，不重发、不换单重付，不删除记录绕过保护，也不回退0.7继续新支付。

详细参数与恢复说明见[支付手册](/cli/支付/)。CLI没有余额、羽币、支付密码、退款、取消或自动续费入口；浏览器提供哪些渠道和履约方式，以对应环境的实际页面为准，不由旧CLI分支推断。

## 用哪个主体处理

| 场景 | 要核对的合同乙方 |
|---|---|
| 主题、插件或普通资源使用依赖 | 当前源资源，身份1；不是作者个人账号 |
| 合集自身声明直接依赖 | 当前合集，身份4；与单品上游映射分开 |
| 节点把来源资源引入为展品 | 当前节点，身份2；不是本地主题资源 |
| 访问者消费展品 | 实际访问者与展品授权上下文，不由以上合同替代 |

以个人身份签订并付款的合同不能替代资源、合集或节点合同；资源合同成功也不能替代节点合同。资金付款人与合同乙方分开核对，授权归属按合同乙方及实际授权状态判断。历史0.7.0曾核验dev资源依赖及节点合同各一笔0.1元微信付款和授权，支付宝旧预支付曾被拒绝；这些事实未覆盖全部策略、合集支付、环境、Console浏览器或平台矩阵，也不构成0.8.0继续提供新支付的承诺。操作步骤见[版本工作稿](/cli/06-版本工作稿)、[节点展品手册](/cli/节点与展品/)及[运行时授权接口](/runtime/api/auth)。
