# 签约、支付与授权：当前边界

CLI 0.7.0已实现独立支付命令，微信扫码在真实dev完成了资源依赖、节点合同各0.1元的两笔验证。0.7.0已发布并完成正常npm客户端下载及安装核验；0.6.1不包含支付命令，先看[版本选择](/cli/00-版本选择与AI代办)。支付宝有命令分支，但当前dev预支付路由返回Cannot POST，仍为BLOCKED，不能称支付宝已可用。

## 五个结果分别核验

| 结果 | 证明什么 | 不证明什么 |
|---|---|---|
| 已选策略并签约 | 对应主体与授权方形成合同 | 已付款或所有条件已满足 |
| 已添加依赖 | 依赖进入当前待发行版本声明 | 节点或访问者可以读取真实内容 |
| 已发行或已上架 | 平台已保存版本/状态并完成相应核验 | 支付自动完成，或每个访问者都已授权 |
| 原订单交易成功 | 该订单的交易状态为succeeded | 合同授权已生效，或其他主体也已获权 |
| 当前授权通过 | 该访问上下文满足平台授权判断 | 换主体、版本、节点后仍一定有授权 |

**策略要求支付后才获得授权时，须完成所需支付并核验授权。** 若策略有试用或其他路径，按实际条款和结果判断，不能仅凭“付费模板”标签猜测。

## 当前 CLI 怎么处理

1. 依赖或节点操作先核验适用合同，必要时按用户明确策略签约；不会自动调用支付。待支付合同可用于部分声明流程，不表示内容已可访问。
2. 用 `payment show <合同ID>` 查看当前合同支付事件和渠道；核对当前账号、环境、乙方主体、事件、渠道和原价。
3. 明确事件与微信渠道后，用 `payment start <合同ID> --event <事件ID> --method wechat` 确认并生成PNG二维码。默认不打开；显式 `--open` 可用系统图片应用打开。最终付款由用户本人扫码确认。
4. 用 `payment status <订单ID>` 分别核对 `paymentStatus` 与 `authStatus`；`--wait`最多五分钟。签约、二维码生成、支付查询命令退出0都不能单独证明付款及授权完成。
5. 需要再次查看原图时用 `payment qr <订单ID> [--open]`，不会创建新单。超时、传输异常或未知结果先查原单；公开start保守阻止同合同事件重复建单，不因失败或二维码过期自动换渠道重付。

详细参数与恢复说明见[支付手册](/cli/支付/)。余额、羽币、支付密码、退款、取消和自动续费未实现。本次节点由支付宝改微信曾使用用户明确批准的一次性现场诊断，保留原单；这不是公开start已支持的通用换渠道能力。支付宝当前dev受后端路由阻塞，不反复预支付或自行更换接口。

## 用哪个主体处理

| 场景 | 要核对的合同乙方 |
|---|---|
| 主题、插件或普通资源使用依赖 | 当前源资源，身份1；不是作者个人账号 |
| 合集自身声明直接依赖 | 当前合集，身份4；与单品上游映射分开 |
| 节点把来源资源引入为展品 | 当前节点，身份2；不是本地主题资源 |
| 访问者消费展品 | 实际访问者与展品授权上下文，不由以上合同替代 |

以个人身份签订并付款的合同不能替代资源、合集或节点合同；资源合同成功也不能替代节点合同。用户可以用个人微信为这些合同付款，授权归属仍按合同乙方及实际授权状态核验。此次真实dev两笔分别核验了资源依赖合同与节点合同的交易成功、authStatus=1，未覆盖全部策略、合集支付、环境、Console浏览器或平台矩阵，也未证明支付宝成功。操作步骤见[版本工作稿](/cli/06-版本工作稿)、[节点展品手册](/cli/节点与展品/)及[运行时授权接口](/runtime/api/auth)。
