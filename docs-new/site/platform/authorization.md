# 签约、支付与授权：当前边界

当前 CLI 支持范围与平台完整业务分开理解。完整正式CLI的目标是与 Console 一致，包含支付；**当前实现暂未接入支付**，本文不把目标写成已实现能力，也不承诺具体交付版本。

## 四个结果不能互相替代

| 结果 | 证明什么 | 不证明什么 |
|---|---|---|
| 已选策略并签约 | 对应主体与授权方形成合同 | 已付款或所有条件已满足 |
| 已添加依赖 | 依赖进入当前待发行版本声明 | 节点或访问者可以读取真实内容 |
| 已发行或已上架 | 平台已保存版本/状态并完成相应核验 | 支付自动完成，或每个访问者都已授权 |
| 当前授权通过 | 该访问上下文满足平台授权判断 | 换主体、版本、节点后仍一定有授权 |

**策略要求支付后才获得授权时，未完成支付就无法取得相应授权。** 若策略另有试用或其他路径，按实际条款和授权结果判断，不能仅凭“付费模板”标签猜测。

## 当前 CLI 怎么处理

- CLI 0.6.0+可以按用户明确选择的策略处理直接依赖或节点展品签约；已经存在的适用合同可复用。
- 当前 CLI 不执行支付，不假装支付成功，不承诺签约后真实文件一定可读。
- 待支付合同在部分流程中可以继续用于声明，但这不代表已满足内容消费条件；后端仍可能拒绝后续操作。
- 需要支付时到对应 Console 或授权处理页面履约，然后以正确主体重新查询或访问验证。未完成时应标“待支付/未获授权”，不能标“可用”。

平台可以提供支付，与 CLI 当前暂不接入并不矛盾。AI 可以说明费用和打开入口，支付由用户本人处理。

## 用哪个主体处理

| 场景 | 要核对的主体 |
|---|---|
| 主题、插件或普通资源使用依赖 | 当前源资源；不是作者个人账号 |
| 合集自身声明直接依赖 | 当前合集；与单品上游映射分开 |
| 节点把来源资源引入为展品 | 节点；不是本地主题资源 |
| 访问者消费展品 | 实际访问者与展品授权上下文 |

个人已付款不能直接证明以上其他主体已获授权；也不能把消费者支付拿来补节点缺失的来源授权。操作步骤分别见[CLI版本工作稿](/cli/06-版本工作稿)、[节点展品手册](/cli/节点与展品/)及[运行时授权接口](/runtime/api/auth)。
