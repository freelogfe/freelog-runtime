# 账号、角色与环境

同一个账号可以创作资源、运营节点，也可以作为访问者消费内容。角色不同不要求强行注册多个账号，但操作主体不能混用。

## 开始前确认四件事

1. **目标环境**：当前CLI教程使用dev，亦支持test；当前CLI拦截prod平台调用。运行时文档站由dev/test共用，不代表两个环境的数据互通。
2. **本人账号**：先使用对应环境的账号服务完成注册或登录；不要把prod账号、dev身份文件或节点地址直接当成test数据。
3. **工具版本**：CLI先按[版本选择](/cli/00-版本选择与AI代办)安装并核验能力。主题插件工具链的Node要求与CLI自身要求分开。
4. **当前对象**：作者发行需要资源ID；节点管理需要节点/展品ID；开发调试需要节点地址与工程目录。

注册及必要的网页登录、身份验证由本人完成。Agent可以说明需要哪些信息、打开正确入口、检查工具和准备工程；不要求你把密码、验证码或Cookie写进提示词。

没有账号时，先打开目标环境的Console（本指南dev入口为 [dev Console](https://console.devfreelog.com/)），使用其登录入口到达账号页面；页面提供注册入口时按实际表单和验证提示创建账号。若该环境未开放注册，应先取得可用账号，不能通过反复CLI登录创建账号。test应使用对应环境入口，不把dev地址替换成正式数据。此过程不需要阅读另一套帮助，也没有假定CLI提供注册命令。

## 登录CLI并确认工作位置

已有账号后，在本次工程目录或用明确的工程路径执行：

```sh
freelog-cli login --cwd <工程目录> --env dev
```

按提示完成登录。已有正确登录时不要反复登录；账号继承、环境切换和退出登录按[环境与凭据](/cli/02-环境与凭据)操作。登录只确定请求账号，不创建资源、节点或展品，也不自动取得任何资源授权。

CLI凭据、Console网页登录态和节点访问者登录态分属各自使用上下文。CLI已登录，不代表浏览器节点中的访问者也已登录或拥有消费授权。

## 对象归属与授权主体

| 操作 | 要确认的身份 |
|---|---|
| 修改作者资源或合集 | 当前账号是该资源所有者 |
| 给资源或合集签依赖 | 当前源资源/合集作为签约主体 |
| 创建或管理节点展品 | 当前账号管理该节点，以节点为签约主体 |
| 在节点消费内容 | 实际访问者按展品策略取得授权 |

以个人身份签订的合同不能替代源资源、合集或节点的合同。用户可以用个人微信为正确的资源、合集或节点合同扫码付款；资金付款人与合同乙方须分开核对。具体区别见[授权与支付](./authorization.md)。标题和昵称可变，不代替资源ID、完整授权标识或节点身份。

## 遇到登录或环境问题

先确认环境、工程目录、账号和对象归属，再按[登录恢复](/cli/09-常见情况与报错)处理。不要通过复制另一环境的身份文件、公开凭据或反复提交写操作来排查。
