# Agent 阅读与操作约定

如果用户不会写代码，先用[人与AI协作入口](/start)收集需求和前提。不要要求用户先学会命令；你负责工程检查和执行，用户负责业务目标、本人认证/支付和体验确认。

## 从这里建立上下文

1. [平台对象](/platform/overview)：先分清作者资源、节点展品、依赖与实例。
2. [运行时结构](/runtime/architecture)：运行时是主应用，主题/插件是浏览器子应用。
3. [版本边界](/runtime/compatibility)：不要混淆资源 semver、运行时目标版本、SDK 包版本和 Node.js。
4. 按任务选择 [CLI](/cli/)、[开发调试](/runtime/development)或 [API](/runtime/api/)。

平台业务与执行入口的对应关系在[任务目录](/platform/tasks)。先判断用户是在作者发行、节点运营还是访问者消费阶段，再选命令或SDK，不把CLI和运行时当成两套割裂的业务。本站应独立提供任务所需知识，不能把关键步骤推给另一套官方帮助。

执行前先按[CLI版本选择](/cli/00-版本选择与AI代办)核对已安装能力和可获得的候选。没有所需候选，不因为文档列了命令就反复尝试正式包；说明阻塞，并按文档选择Console替代路径。

## 不使用浏览器时

- [llms.txt](/llms.txt)：页面索引与建议阅读顺序。
- [llms-full.txt](/llms-full.txt)：全文，适合下载后检索；内容多时优先按页读取。
- Markdown 正文：从 `llms.txt` 中取得对应的 `/markdown/…​.md` 地址，与页面正文同源，不必解析页面 HTML。
- [来源记录](/source-lock.json)：CLI 版本、提交、是否含未提交文档、逐页摘要。

这些入口帮助发现正文，不会授权 Agent 执行远端写入，不包含登录态或账号凭据。

## 调用与验证

CLI 优先使用 JSON 输出和明确资源/环境；先看本地状态，再编辑。没有工作稿不能把线上版本当成本地稿。远端结果未知时先查，不重复发行。

运行时 API 先核对作用域、参数、同步/异步和返回信封。当前实时查询与缓存查询不保证相同返回层级，不能根据函数名称猜。示例占位符必须替换，不把 `<资源ID>` 当真实值。

截图不是字段协议，页面出现“未来”“未实现”“待核验”不能据此生成接口。资源信息查询、真实文件访问和插件挂载分别验证。

当前CLI暂不执行支付。策略要求先支付才能授权时，未支付无法取得相应授权；不得把签约成功、待支付合同、依赖声明或版本发行说成支付/授权完成。具体主体见[支付边界](/platform/authorization)。

## 当前文档边界

本次CLI内容已同步并核对已发布npm 0.6.0的手册，新增命令需要0.6.0+；0.5.9不支持这些新增路径。具体版本及保留的验收限制见[文档状态](/about)。运行时内容按仓库源码核对，尚未证明线上部署对应当前提交，不能因此承诺所有SDK调用已在该环境实测。
