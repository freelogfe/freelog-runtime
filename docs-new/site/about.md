2026-11-13校准0.8.0的节点/展品管理、JSON回执、验证码登录和模板/存储修复。此前0533f17与npm0.7.0包内20份手册的一致性核验只证明当时的冻结正文，不能用于证明当前正文与0.8.0的registry下载包一致。npm接受发布请求不等于下载与安装核验完成；本轮随后已实际下载0.8.0，核对候选SHA-512、安装入口及20份手册通过。文档构建仍不等于线上已部署。

CLI正文通过脚本从唯一源手册同步，不是在站点手改的副本。历史上曾核对npm0.6.0、0.6.1以及0.7.0归档手册；核验记录见维护记录，不能移用为当前开发稿与npm包一致的证明。`source-lock.json`记录当前源提交、dirty标记和逐页摘要，`channel: development`不代表npm发行。后续源手册变化时需重新同步核对，不能仅凭版本字符串相同认定正文与npm包一致。

CLI 0.8.0仍处开发阶段：完整命令/业务覆盖证明、Console双向及三平台完整验证尚未闭合，固定合集策略模板仍有已知后端编译失败，Windows密码取消有既定单例隔离。网页核验本轮延期，手机/邮箱验证码登录已支持但真人体验未验，微信登录待后端。已完成的专项测试不等于全部场景通过。节点新展品签约使用内联auth-cli；依赖、已有展品、合集单品上游的新签约及所有新支付转浏览器，CLI保留正确主体的已有合同校验和历史原单查询恢复。请按[版本选择](/cli/00-版本选择与AI代办)和[错误处理](/cli/09-常见情况与报错)操作，不把发行或签约成功当真实访问已获授权。

历史上0.7.0曾提供微信二维码准备，dev资源依赖及节点两笔各0.1元由用户扫码后核验成功，支付宝旧预支付路由曾被拒绝。旧包首页与包内说明存在文案差异；这些历史事实及旧包内容不被本站改写，也不构成0.8.0继续提供新支付的承诺。不要为支付回退旧包、重开旧单或更换渠道。

## 迁移处理

- 核心入门、架构、版本、开发与发行重新按任务编写，不靠截图提供关键字段。
- API 参考保留完整接口，修正已确认的方法名、示例与返回层级问题；没有对应真实环境逐接口执行，不能把文档修正当成全部 SDK 通过测试。
- 框架和库示例保留为进阶参考，适用技术版本与示例文件分别说明，不把历史工具链当平台限制。
- CLI 页面自动同步，禁止在站点手工改写命令。签约主体、已有合同校验、新签约及支付的边界统一在源手册维护，由脚本同步；签约、交易与授权状态仍分别核验。

## 已知限制

1. 当前运行时没有通用的资源 ID 直接查询入口；本地新增依赖不自动产生真实展品依赖路径。
2. 未发行依赖的模拟方案已撤下；不提供直接下载的替代路径。
3. 源码 `getSelfProperty` 的依赖分支存在未等待请求的实现问题，新站标注限制，不借整理文档修运行时。
4. dev/测试站点部署对应关系尚未确认。历史两笔微信专项实测不覆盖全部SDK、策略或环境，也不证明0.8.0的新支付能力；网页、验证码真人体验、补贴/过期/关闭幂等和完整平台矩阵仍未验。

## 新站维护

正文、图片和代码示例都要可独立阅读。多阶段步骤先给主线，再写前提、执行和结果；图表配文字，示例配上下文和返回层级。

新站构建拒绝失效页面链接，生成的 CLI 内容有摘要校验。网站能构建、能搜索，不代表文档中的所有业务流程已在平台验证。
