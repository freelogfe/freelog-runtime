# 文档版本、来源与迁移状态

新版文档工作目录为运行时仓库 `docs-new`；旧 `packages/docs` 没有因本次重构被替换或修改。本次本地更新不等于线上已部署，访问线上站点时须另外核对来源。

## 三类版本分别注明

| 范围 | 当前依据 | 说明 |
|---|---|---|
| 运行时主应用 | 本地源码 `2fa5f83f` | 基于本地维护的 MicroApp 改造版，不能直接将上游最新版行为当现状 |
| 类型/接入包 | 仓库 `freelog-runtime` 5.0.7 | 主题/插件的 SDK 兼容范围见版本页，不等于 Node.js 版本 |
| CLI 手册 | CLI仓库根`docs/`同步的当前正文 | 精确revision、dirty、包版本及逐页摘要见同步记录；开发正文不等同npm已发行正文。授权及支付边界见[手册首页](/cli/) |

精确 CLI 来源见[同步记录](/source-lock.json)，包含原始与生成正文摘要。同步时间不作为发布批准；`dirty` 表示文档或包元数据含未提交改动。

CLI正文通过脚本从唯一源手册同步，不是在站点手改的副本。`source-lock.json`记录当前源提交、dirty标记和逐页摘要，`channel: development`不代表npm发行。后续源手册变化时需重新同步；不能凭版本字符串相同或旧包验收结果认定当前正文与npm包一致。历史验证事实保存在维护记录，不当成当前操作教程。

完整命令/业务覆盖证明、Console双向及三平台完整验证尚未闭合，固定合集策略模板仍有已知后端编译失败，Windows密码取消有既定单例隔离。手机/邮箱验证码登录的PNG展示及人工/Agent操作方式见[登录教程](/cli/02-环境与凭据)，具体构建和终端体验按对应验证记录判断；微信登录待后端支持。专项测试不代表全部场景通过。

节点新展品签约使用内联auth-cli；依赖、已有展品、合集单品上游的新签约及所有新支付转浏览器。依赖可以先保存本地声明，正式发行前才核对正确主体的合同；完整依赖授权新链仍未开放。CLI保留历史原单只读查询及恢复，不生成新订单或二维码。请按[版本选择](/cli/00-版本选择与AI代办)和[错误处理](/cli/09-常见情况与报错)操作，不把发行、签约或查单成功当真实访问已获授权，也不要为支付回退旧包或重开旧单。

## 迁移处理

- 核心入门、架构、版本、开发与发行重新按任务编写，不靠截图提供关键字段。
- API 参考保留完整接口，修正已确认的方法名、示例与返回层级问题；没有对应真实环境逐接口执行，不能把文档修正当成全部 SDK 通过测试。
- 框架和库示例保留为进阶参考，适用技术版本与示例文件分别说明，不把历史工具链当平台限制。
- CLI 页面自动同步，禁止在站点手工改写命令。签约主体、已有合同校验、新签约及支付的边界统一在源手册维护，由脚本同步；签约、交易与授权状态仍分别核验。

## 已知限制

1. 当前运行时没有通用的资源 ID 直接查询入口；本地新增依赖不自动产生真实展品依赖路径。
2. 未发行依赖的模拟方案已撤下；不提供直接下载的替代路径。
3. 源码 `getSelfProperty` 的依赖分支存在未等待请求的实现问题，新站标注限制，不借整理文档修运行时。
4. dev/测试站点部署对应关系尚未确认。历史支付专项实测不覆盖全部SDK、策略或环境，也不证明当前可发起新支付；完整网页双向、全部终端/平台及补贴、过期、关闭幂等仍未完成全面验证。

## 新站维护

正文、图片和代码示例都要可独立阅读。多阶段步骤先给主线，再写前提、执行和结果；图表配文字，示例配上下文和返回层级。

新站构建拒绝失效页面链接，生成的 CLI 内容有摘要校验。网站能构建、能搜索，不代表文档中的所有业务流程已在平台验证。
