# 文档版本、来源与迁移状态

新版文档工作目录为运行时仓库 `docs-new`；旧 `packages/docs` 没有因本次重构被替换或修改。本次本地更新不等于线上已部署，访问线上站点时须另外核对来源。

## 三类版本分别注明

| 范围 | 当前依据 | 说明 |
|---|---|---|
| 运行时主应用 | 本地源码 `8ea709d0` | 桌面与移动端统一登录已进入源码，实际部署按节点验收 |
| 运行时接入包 | npm 包 `freelog-runtime` 5.0.7 | 提供主题和插件的初始化方法与 TypeScript 类型，版本关系见[兼容性与版本](/runtime/compatibility) |
| CLI 手册 | [同步记录](/source-lock.json)中的包版本与提交 | [CLI 手册](/cli/) |

本站从 CLI 仓库的根使用手册同步。`channel: development` 表示本构建用于 dev 或测试环境，`dirty: true` 表示同步包含尚未提交的手册改动。手测时核对全局命令的安装来源。正式 npm 包以其发布版本为准。[同步记录](/source-lock.json) · [npm 安装包](https://www.npmjs.com/package/@freelog/cli)

用 `npm ls --global --depth=0` 确认全局安装的包名，用 `freelog-cli --cli-version` 核对版本。更换全局安装来源时，按手册操作。[安装与切换](/cli/00-版本选择与AI代办#从旧包迁移)

完整命令/业务覆盖证明、Console双向及三平台完整验证尚未闭合，固定合集策略模板仍有已知后端编译失败，Windows密码取消有既定单例隔离。手机/邮箱验证码登录的PNG展示及人工/Agent操作方式见[登录教程](/cli/02-环境与凭据)，具体构建和终端体验按对应验证记录判断；微信登录待后端支持。专项测试不代表全部场景通过。

节点新展品签约使用内联auth-cli；依赖、已有展品、合集单品上游的新签约及所有新支付转浏览器。依赖可以先保存本地声明，正式发行前才核对正确主体的合同；完整依赖授权新链仍未开放。CLI保留历史原单只读查询及恢复，不生成新订单或二维码。请按[版本选择](/cli/00-版本选择与AI代办)和[错误处理](/cli/09-常见情况与报错)操作，不把发行、签约或查单成功当真实访问已获授权，也不要为支付回退旧包或重开旧单。

自动化签入展品时提供有效的 `--name`。收到平台明确的权限拒绝时，按错误提示检查账号与节点权限。创建结果不确定时，先查询节点展品再决定后续操作。[签到节点](/cli/授权与支付/签到节点)

## 迁移处理

- 核心入门、架构、版本、开发与发行重新按任务编写，不靠截图提供关键字段。
- API 参考保留完整接口，修正已确认的方法名、示例与返回层级问题。各接口在真实节点中的执行结果仍待逐个核验。
- 框架和库示例按 Freelog 实际接入能力维护。主题和插件通过 `freelog-runtime` 接入节点运行时，路由、通信及生命周期见[应用接入](/runtime/integration/)。
- CLI 页面自动同步，禁止在站点手工改写命令。签约主体、已有合同校验、新签约及支付的边界统一在源手册维护，由脚本同步；签约、交易与授权状态仍分别核验。

## 已知限制

1. 当前运行时没有通用的资源 ID 直接查询入口；本地新增依赖不自动产生真实展品依赖路径。
2. 未发行依赖的模拟方案已撤下；不提供直接下载的替代路径。
3. 源码 `getSelfProperty` 的依赖分支存在未等待请求的实现问题，新站标注限制，不借整理文档修运行时。
4. dev/测试站点部署对应关系尚未确认。历史支付专项实测仅覆盖当时选定的策略和环境，当前发起新支付仍按[支付边界](/platform/authorization)办理。完整网页双向、全部终端和平台，以及补贴、过期和关闭幂等仍待全面验证。

## 新站维护

正文、图片和代码示例都要可独立阅读。多阶段步骤先给主线，再写前提、执行和结果；图表配文字，示例配上下文和返回层级。

新站构建拒绝失效页面链接，生成的 CLI 内容有摘要校验。网站能构建、能搜索，不代表文档中的所有业务流程已在平台验证。
